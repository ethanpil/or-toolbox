# ORtoolbox — developer and agent guide

Browser-only toolbox of 14 AI tools on top of OpenRouter. No server, no accounts. The product spec is [PLAN.md](PLAN.md); the OpenRouter API facts we code against are in [docs/openrouter-api.md](docs/openrouter-api.md). Read both before changing behaviour. This file records the architecture rules and the non-obvious decisions.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server on :5273 under `/or-toolbox/` (no service worker; sends the isolation headers itself and a dev CSP built from the production table) |
| `npm run build` | Typecheck + production build to `dist/` (also emits `sw.js` and copies the ffmpeg cores) |
| `npm run preview` | Serve `dist/` on :4273 (service worker and CSP active) |
| `npm run check` | Typecheck + lint + unit tests — run before reporting any work done |
| `npm run typecheck` / `lint` / `format` | `tsc` on the three projects / ESLint + Prettier check / Prettier write |
| `npm run test` | Vitest unit tests |
| `npm run e2e:dev -- <spec>` | Playwright against the dev server (reuses a running one) — use this while developing |
| `npm run e2e` | Build, then Playwright against `preview` — the gate run; do not run it while other agents are working (it rewrites `dist/`). `E2E_SKIP_BROWSERS=firefox` leaves out a browser this machine cannot run; CI never sets it |
| `npm run icons` | Regenerate `public/icons/*.png` and `favicon.ico` from `public/icons/logo.svg` (outputs are committed) |

## Layout

```
index.html, settings/, models/, history/, stats/, privacy/, diagnostics/,  platform pages (tiny HTML entry each:
auth/callback/                                                             <title>, <div id="app">, one module script)
tools/<id>/index.html                                                     one page per tool
src/core/        one folder per service (api, keys, oauth, models, settings, runs, budgets, history, prompts,
                 jobs, stats, results, tool-state, backup, data, bus), media/, export/, storage/, attachments/
                 (chat-request files: Chat, Model arena); contract in types.ts, errors in errors.ts, shared
                 helpers in util.ts, composition root in index.ts
src/ui/          dom.ts, markdown.ts, format.ts, bootstrap.ts (the only Bootstrap JS imports), shell/ (mountPage,
                 navbar, palette, leave guard, appearance), feedback/ (toasts, dialogs, presentError), components/
                 (shared parts), tool/ (mountTool and the tool contract)
src/tools/<id>/  manifest.json + main.ts (+ tool-local modules and tests); registry.ts + types.ts beside them
src/pages/       code for the platform pages
src/styles/      main.scss (Bootstrap + Bootstrap Icons + the few variable overrides in _variables.scss)
src/sw/          the single service worker (sw.ts)
public/          theme-init.js, manifest.webmanifest, icons/, .nojekyll — copied to dist/ as-is
vite-plugins/    page discovery, shared <head> + CSP, ffmpeg core copying, service worker build, ports/base
scripts/         one-off generators (icons)
tests/e2e/       Playwright specs (sw/ = service-worker specs)   tests/mock/  mocked OpenRouter   tests/fixtures/  recorded/documented responses and media
tests/lint/      proof that the ESLint architecture rules fire
```

Adding a page = adding a folder with an `index.html`; the build, dev server and route tests all discover it (`vite-plugins/pages.ts`). The shared `<head>` (charset, CSP, viewport, theme colour, manifest, icons, `theme-init.js`, the stylesheet) is injected by `vite-plugins/html-head.ts`; HTML entries must not repeat it.

TypeScript is three projects behind a solution-style `tsconfig.json`: `tsconfig.app.json` (src/, DOM), `tsconfig.sw.json` (src/sw/, WebWorker), `tsconfig.node.json` (configs, vite-plugins/, tests/e2e, tests/mock, tests/lint; imports use `.ts` extensions).

Tool ids (also the URL segment): `chat`, `ocr`, `data-extractor`, `table-extractor`, `speech-to-text`, `text-to-speech`, `music-generation`, `image-generation`, `image-editor`, `isolated-image`, `video-studio`, `decision`, `bot-to-bot`, `model-arena`.

Capabilities (keys for default models): `text`, `vision`, `image`, `tts`, `stt`, `video`, `music`, `decisions`.

## Architecture rules

1. **Pages never call OpenRouter or storage directly.** Tools and pages go through `src/core`. Only `src/core/api` may `fetch` openrouter.ai; only `src/core` may touch `localStorage`, `sessionStorage` or IndexedDB. This is what keeps keys, budgets, cost tracking and history consistent.
2. **Every model call belongs to a run.** A tool starts a run through the context (`ctx.runs`), which applies free-only mode and budgets before the request, captures usage/cost from every response, writes text-only history and feeds stats. Never call the API outside a run except for catalog/key/status reads.
3. **History is text only.** Images, audio, video and uploaded files stay in memory and are registered with the leave-page guard until downloaded. Never write binaries to IndexedDB or localStorage.
4. **Tool contract.** `src/tools/<id>/manifest.json` describes the tool; the shape is `ToolManifest` in `src/tools/types.ts` (PLAN.md's example plus a one-line `description`, minus `entry`, which the folder convention makes redundant; `capabilities` use the list above). `src/tools/registry.ts` collects and validates the manifests. `main.ts` calls `mountTool(manifest, setup)` and receives one context object; [docs/tool-authoring.md](docs/tool-authoring.md) is the guide (contract, runs, results, jobs, prompts state, testing, a worked example). Tools use the shared components (drop zone, model picker, key chip, cost estimate, prompts panel, output panel, players, exporters) instead of rebuilding them. A tool folder may not import from another tool folder; shared code moves to `src/core` or `src/ui`.
5. **Three-zone tool layout:** input left, output right, settings in an offcanvas drawer; advanced options in an accordion. Stacks on narrow screens.
6. **Plain Bootstrap 5.3.** Stock components and Bootstrap Icons. Customisation is limited to the Sass variables in `src/styles/_variables.scss`. No UI framework, no CSS-in-JS, no custom component library. Small utility CSS for things Bootstrap lacks is fine.
7. **No third-party origin at runtime.** Everything is bundled and self-hosted. The only network destinations are the static host and `https://openrouter.ai`.
8. **Heavy libraries are lazy.** pdf.js, ffmpeg.wasm, docx/xlsx writers, the chart library and the markdown renderer load with dynamic `import()` only when used. Budgets: shell ≤ 150 KB gzipped JS, each tool ≤ 80 KB more.

## Conventions

- TypeScript strict; ES modules; no `any` without a comment explaining why.
- Errors the user can act on are `OrError` subclasses from `src/core/errors.ts` (each has a `code`; the shell switches on `errorCode()`); never throw bare `Error`s for them. Small shared helpers (abort/sleep, type guards, prototype-safe JSON, UTC days) live in `src/core/util.ts`: import them instead of writing local copies (the token approximation is `approxTokens` in `src/core/tokens.ts`; Chat still has its own copy). Data parsed from storage, files or the network goes through `parseJsonSafe`/`readJson` and is validated before use.
- Build DOM with the `h()` helper in `src/ui/dom.ts` (its header lists the rules: prop order, handlers, URL props limited to http(s)/mailto/tel/blob/relative, refused tags and props). Never put model output, file names or any other untrusted string into `innerHTML`. Markdown from models goes through `renderMarkdown()` (marked + DOMPurify), which also turns remote images into links so rendering never contacts another host.
- No inline scripts or inline event-handler attributes (CSP is `script-src 'self'`). No inline `style=""` attributes in HTML strings; set styles through CSSOM or classes.
- Internal links and asset URLs go through `url()` in `src/core/paths.ts`, because the site is served from `/or-toolbox/` on GitHub Pages.
- API keys are never logged, never placed in URLs, never written to history, and are masked in the UI (`sk-or-…a1b2`).
- Accessibility is part of done: labelled controls, keyboard reachable, visible focus, `aria-live` for streaming/status, contrast checked in light and dark.
- Motion is 150–250 ms, transform/opacity only, and off under `prefers-reduced-motion` or the Reduced motion setting.
- Unit tests live next to the code as `*.test.ts` (Vitest, jsdom; tests needing IndexedDB `import 'fake-indexeddb/auto'`). E2E specs live in `tests/e2e/`, import `test`/`expect` from `tests/mock/index.ts` (never from `@playwright/test` directly) and only talk to the mocked OpenRouter; no test may reach the real API. Use `watchForProblems()` from `tests/e2e/support.ts` to assert a page has no console errors, failed requests or CSP violations (it ignores `net::ERR_ABORTED` on `<audio>`/`<video>` reads of `blob:` URLs; aborts the app causes, a Stop or a stream cancelled after `[DONE]` in production builds, are opt-in: `watchForProblems(page, { allowAborted: ['/api/v1/chat/completions'] })`), and `seedApp(context, { settings, key })` from `tests/e2e/app.ts` to start with onboarding done (and a test key).
- ESLint enforces two of these rules (proved by `tests/lint/`): no HTML-string sinks (`innerHTML`/`outerHTML` in any spelling, `insertAdjacentHTML`, `setHTMLUnsafe`, `parseHTMLUnsafe`, `createContextualFragment`, `document.write`), and no `localStorage`/`sessionStorage`/`indexedDB` outside `src/core` (also via `window.`/`self.`/`top.`/`parent.`).
- Dependencies: assume your knowledge of every library is outdated. Check the installed version's docs or types before using an API. Do not add a dependency if one already in `package.json` does the job.
- Changelog: `CHANGELOG.md` in Keep a Changelog format, short entries, with the commit hash when known.

## Shell and UI (Stage 2)

- **Every page** is `mountPage(options, render)` (`src/ui/shell/index.ts`): boot, appearance, navbar, `<main id="main">`, footer, one `<h1 data-testid="page-title">` (pass `header: false` to render your own), palette (Ctrl/Cmd+K), leave guard, budget confirmation (`runs.setConfirmHandler`), auto-lock activity. Script navigation goes through `page.navigate()` so the leave guard sees it. **Tool pages** are `mountTool(manifest, setup)` (`src/ui/tool/`), which calls `mountPage`.
- **Deep links** live in `src/ui/shell/links.ts`. The Settings page must give every `SETTINGS_SECTIONS` id (`keys`, `models`, `tools`, `budgets`, `appearance`, `security`, `data`, `backup`) an element and open it from the URL hash; the palette, errors and onboarding link there. History reads `?tool=` and `?run=`; Models reads `?q=`; tools read `?run=`, `?prompt=`, `?model=`, `?sample=1`, `?receive=`.
- **Feedback:** `presentError(error, { retry })` switches on `errorCode()`; throw `OrError`s and let it decide. Toasts announce through two persistent live regions (`announce()`), never by being live regions; a toast with an action never hides by itself (WCAG 2.2.1) and its actions run once. `openModal()` is the only modal builder: one at a time, later calls queue (`modalOpen()` tells shortcuts to stay out); `hide()` during the show transition is deferred, Bootstrap would drop it. Parallel budget confirmations of one `groupId` share one dialog, and parallel no-key errors one add-key dialog. Field validation goes through `setFieldError(input, feedback, message)`. Offcanvases opened from code use `showOffcanvas()` so focus returns to the opener; Bootstrap keeps only one focus trap, so a modal closing over an open offcanvas re-arms it (`restoreOffcanvasTrap()`).
- **One error rule** (tools): Stop (`aborted`/`cancelled`) is silent apart from a neutral "Stopped"; errors that need an action (no key, locked, free-only, budget, storage) always go to `presentError`; any other error is shown once, inline by `outputPanel.fail(error)` (which marks it presented) or else by the runner's `presentError`. `presentError` ignores an error it has already shown.
- **Shared UI helpers** (use them; do not write a local copy): `format.ts` has `formatInt`, `formatDate` (a timestamp, or a `YYYY-MM-DD` UTC day), `keyBalance` and the rest, so no page calls `toLocaleString`/`toLocaleDateString`; `DAY_MS`/`HOUR_MS`/`MINUTE_MS` and `debounce(fn, ms)` (cancelable; `SEARCH_DEBOUNCE_MS` for search boxes) are in `core/util.ts`; `clipboard.ts` has `copyWithToast`; `settings-actions.ts` has `saveSettings` (shows a failed save; `onError` replaces that), `setToolBinding`, `toggleFavouriteModel`/`toggleFavouriteTool`, `setTheme`, and `THEME_MODES` is in `shell/appearance.ts`; `core/models/capabilities.ts` has the one `CAPABILITY_INFO` (`label` for sentences, `title`, `badge`, `filter`, `icon`); `findTool(id)` in `tools/registry.ts` is the lookup for ids from storage (`getTool` throws). Components (`src/ui/components/`): `starButton`/`setStarred`, `dataTable` (scroll region with `position-relative`, named and focusable, `th scope`, numeric columns from `numericFrom`; pass your own `body` when the page re-renders its rows), `keyBalanceView` (one state machine and wording for Settings, Stats and the key menu), `loadInto` (skeleton, status text, error state with Try again; a newer call on the same container supersedes an older one; `keepOnLiveFailure` for live reloads), `externalLink`, `switchField`, `meter`, `createMarkdownCache` (finished messages rendered once, with an optional `decorate`; Chat's code Copy buttons), `attachmentIntake({ noun, … })` (dropped, pasted and "Send to…" files with one set of limits and wording: Chat's composer, the arena's prompt). Costs are worded by `describeRunCost`/`formatRunCost`/`usageLine` in `format.ts` and nowhere else: unknown first (never free or `≈`; says what budgets counted for it), then free, estimated (`≈`), known. An error shown inline goes through `failureText(error, { blind })` (`feedback/errors.ts`), which keeps the "may have gone through and been billed" caution and the activity link that bare `userMessage` drops; with `outcomeUnknown` offer no plain Retry. `blind: true` (the arena before names are shown) makes every failure read alike (generic text, `BLIND_ACTIVITY_NOTE`, the activity link, `outcomeUnknown` false), because a 402's credits, the 429 text about free models, provider names or a missing Retry would give a paid model away. Small icon-only buttons are `btn btn-sm btn-link or-icon-action` (`.or-icon-button` is the Models page's compact copy button). Searching a catalog goes through `rankBy` (`shell/palette-search.ts`): the query is normalised once per search and each object's fields once, cached per `describe` function. Global shortcuts follow `shell/shortcuts.ts`: a plain key (Home's `/`) is ignored in fields, selects and dialogs; Ctrl/Cmd+K works in fields but never opens over another dialog (and then the browser keeps the key).
- **Re-rendering keeps focus** through `replace(container, ...children)` (`src/ui/dom.ts`): the focused control's `data-focus-key` is looked up again in the new children (if it is gone or disabled, the nearest keyed control that can take focus, following ones first, then the first focusable element), and Bootstrap instances inside the old ones are disposed. `focusedKey(root)`/`focusKey(root, key)` do the same for a single node a tool swaps itself, and `replaceWith(el, children, { fallback })` lets a page pick the landing place first (Settings uses it for its section headings). Product code never reads `data-testid`.
- **Bootstrap JS** is imported per plugin from `bootstrap/js/src/*.js` (typed in `src/ui/bootstrap-js.d.ts`); data attributes (`data-bs-toggle`) work because each import registers its data API. Never the bundle.
- **Look:** canvas `--or-canvas` behind `--or-surface` cards (light: grey behind white; dark: body behind tertiary), `--or-inset` for recessed areas. Bootstrap's outline buttons are re-coloured in `_shell.scss` because their stock text colours miss AA on the canvas (secondary) and in dark mode (primary, danger, success). A global `[hidden] { display: none !important }` beats display utilities. Custom CSS is one partial per concern in `src/styles/`.
- **Accent colour** is applied at run time: `src/ui/shell/accent.ts` derives Bootstrap's shades (same tint/shade weights) plus link and outline text at 4.5:1 on every surface of the theme (light: white cards and the `--bs-tertiary-bg` canvas; dark: body and card), focus outlines and the focused-field border at 3:1 (`--or-focus-color`/`--or-focus-border`), and check/radio/switch glyphs in `--or-accent-contrast` (SVG data URIs as custom properties); `accent.test.ts` checks this over a colour sample, `appearance.ts` sets them on `<html>` with `data-accent`, and `_accent.scss` re-points the components Bootstrap compiled with fixed colours. Theme and accent changes switch with transitions paused for two frames (`data-no-transition`), so nothing animates its colours.
- **theme-init.js** also sets `data-density` and `data-reduced-motion` before first paint, handles the incoming view transition (`pagereveal`, which fires before any module runs) and silences only Chromium's "Transition was aborted/skipped" rejections: on a busy machine Chromium aborts cross-document transitions and rejects a promise no script can reach (measured; navigation is unaffected).
- **The command palette opens without Bootstrap's fade** (`animate: false`): a fading modal is unfocusable until its backdrop finishes, and keystrokes typed right after Ctrl+K would land on the page.
- **Send to…** hands items over in memory: the source opens `tools/<id>/?receive=<id>` and answers the target's `ready` on BroadcastChannel `ortoolbox:send`; nothing is stored. jsdom cannot structured-clone its own Blobs, so the unit test checks the handshake, not Blob bytes.
- **Tool framework internals** (`src/ui/tool/`): the page-wide drop/paste guard (`file-drop.ts`) is installed before `setup`, so a stray drop never navigates away. Estimates come from `ToolInstance.estimate(model)` through `estimate.ts` (a version counter drops answers older than the newest request); `ctx.beginRun` books the latest one. `createToolContext` (`context.ts`) is shared by the page and `createToolTestContext` (`testing.ts`, the tool unit-test harness). Every tool's main prompt field is `data-testid="tool-prompt"` (unless the instance is `promptless`). The sticky Run bar keeps focus visible: `--or-runner-height` feeds `scroll-padding-bottom`, and since Chromium ignores scroll padding for Tab, a focused control it still covers is scrolled up on the next frame. `RunnerOptions.replayArg` (`pendingOnly(isDone)`) narrows the toast Retry to items without a result. The leave guard ignores handed-off runs (`RunHandle.jobId`): the job carries on without the page, and lists work a tool holds with `ui.holdWork()` (`results.hold()`), which also arms the browser's prompt. The status line is not a live region: `ui.status` announces through `announce()`, `ui.progress` at most every 10 s (`status-line.ts`). `ctx.beginRun` always computes the estimate afresh (a tool's debounced refresh may lag the input); only `ui.setEstimate` values are reused. Per-item Retry goes through `retryGate(runner)`, bars through `progressBar()`, audio results through `audioResultCard()`, image results through `imageResultCard()`.
  - **Runner arguments:** `trigger(arg)` passes `arg` to `run(signal, arg)` and the error toast's Retry replays the same `arg`. `trigger()` returns `Promise<void> & { started }` rather than `Promise<boolean>` so existing `Promise<void>` callers still type-check; `subscribe` reports `{ busy, disabledReason }` for a tool's own Retry buttons.
  - **A bar with more than Run** is built on the runner: `runner.setLabel()`, `RunnerOptions.hideWhileBusy`, and `runner.addAction({ label, run: arg | onClick, when: 'idle' | 'busy', … })` (a `run` action is off exactly when Run is, with Run's reason; it returns `setLabel`/`setDisabled(reason)`). The runner hands focus to the first visible bar control when the focused one hides (for every runner), and Ctrl/Cmd+Enter stays Run with no argument. `stopOnEscape(runner, { allowIn })` (`stop-on-escape.ts`) is the one Escape-to-stop handler, on `plainShortcutAllowed` (so Ctrl/Cmd/Alt+Escape, dialogs, fields and an open drawer or menu are left alone); `composing(event)` is in `shell/shortcuts.ts`. Tools never rebuild the bar by hand.
  - **Tools that choose their own models** set `"ownModels": true` in their manifest (Model arena, Bot-to-bot; there is no mount option): the header drops the model chip and the free-only substitution note (Run is still disabled with the notice when free-only leaves no model), and Settings → Tools shows "Chosen inside the tool" instead of a picker. Their binding is only the starting model of a new setup (arena contenders, a bot without its own model), so no UI writes it; an old one is shown and Reset clears it.
  - **Batches** go through `runItems()` (`batch.ts`, over `runPool`): per-item statuses, a fatal error (`isFatalError`) stops scheduling and is rethrown unmarked (it needs presenting), an all-failed batch rethrows its last error marked as shown (the items show it), Stop rethrows the abort reason.
  - **Paid add-ons** (`RunSpec.addons`, `src/core/runs/addons.ts`): each has its own estimate; `runs.begin` adds known parts to the models' estimate (null only when nothing is known) for budgets and the reservation, refuses a paid one (estimate not 0, unknown included) in free-only mode, and a run with one is never "free" for budgets. Tools declare them with `ToolInstance.addons()`; the badge shows model + add-ons (unknown model cost stays Unknown). PDF engines and the Mistral OCR page price ($2.20 per 1,000 pages, the announced $2 plus the 10% US regional rate; the docs page does not render the number) live in `src/core/models/pdf-engines.ts`.
  - **Streaming** text is drawn by `streamMarkdown()` (`src/ui/components/stream-markdown.ts`); `outputPanel` is a shell around it. `exportMenu()` returns its element with `update()`, so it is built once (rebuilding closed an open menu).
- **Onboarding** is an inline wizard on Home (a modal would block Home for every first visit and every e2e test); its step is kept in `settings.ui['home.onboardingStep']` so the OAuth round trip comes back to it.
- **Settings** (`src/pages/settings.ts`, sections in `src/pages/settings/`): one panel per `SETTINGS_SECTIONS` id, chosen by the hash; `hashchange` focuses the section's `<h2>` (that is the announcement), and a non-section hash such as the skip link's `#main` is ignored. A section is built when it is first shown (a visit to `#keys` never loads the model catalog or subscribes the other sections), loads its numbers then (`onShow`) and re-renders from service subscriptions through `rerender()`, which gives focus back by `data-focus-key` (`replace()`), or else to its `fallback`. Undo of a key removal re-inserts the removed key (same id, so its stats and budget follow) into the keys file as it is at Undo time, via `keys.replaceFile(next, { expected: current })`, and restores its default/tool pins/per-key budget only where nothing replaced them; the removed entry is held in memory only until the toast closes. `freeOnlyModel()` in `logic.ts` mirrors `ModelsService.resolve` with free-only on, so the page can preview free-only mode while it is off; a unit test keeps the two in step.
- **`.visually-hidden` inside a scroller:** it is absolutely positioned, so in an unpositioned `.table-responsive` it escapes the overflow and widens the page on phones. Give the scroller `position-relative`.
- **Dev-only e2e:** `tests/e2e/dev/` (like `media/`) imports the page's own core from `/src`, so it runs only against the dev server (`npm run e2e:dev -- tests/e2e/dev`) and no test hook ships. It covers states no built tool can produce yet (pending results, runs in progress, budget confirmation).

## Platform pages: Models, History, Stats

Each is a class in `src/pages/<page>.ts` over a pure module (`models-logic`, `history-logic`, `stats-logic`, unit-tested) that holds every rule about filtering, paging, grouping and aggregation; the page only draws. E2E specs seed IndexedDB through `tests/e2e/seed.ts` (`seedDb`: runs and stats rows, then a bus message so open pages update live).

- **Models:** the catalog (~650) is filtered in memory and drawn 48 at a time ("Show more", and automatically through `whenVisible()` in `src/pages/lazy.ts`), so no virtual list is needed. Free means `:free` id only (zero prices are not a signal). **Prices come from one model, `src/ui/model-price.ts`** (`modelPrice`, `describePrice`, `comparablePrice`), which `formatModelPrice` in `format.ts` delegates to, so the picker, the tool chip, Settings and this page agree: the unit is the model's real billing unit (per 1M tokens, per image, per 1M characters or bytes, per hour of audio, per second of speech, per clip, per request, or "varies" for video and routers), chosen with the same heuristics as `src/core/models/estimate.ts`; token-priced chat models with audio or image output get an extra line. Sorting by price puts free first, then each unit on its own (never comparing an image price with a token price). "Max price" compares input plus output per 1M tokens in micro-dollars, free always passes, and models billed in another unit never do: the page says how many that hides (`hiddenByPriceLimit`). Your own stats per card come from one read of the ledger (`usageByModel`, rebuilt on `stats.subscribe`), never one query per card. A "Retry" after a failed load asks the network (`refresh: true`): the cache remembers a failure for five minutes. The card/table choice is `settings.ui['models.view']`; `?q=` is kept in the address bar with `replaceState`.
- **History:** pages by cursor `before = last.startedAt + 1` and drops rows already shown, because parallel runs (arena) can share one millisecond and an exclusive cursor would skip them; "Show more" appends only the new rows. **`HistoryService.restore(runs)` is the one core addition of the pages stage** (Undo for delete, like `prompts.restore`; it never touches stats). Runs in progress are never deleted (not one by one, not by "Delete filtered", which says how many it kept), so Undo can never bring one back. Delete asks first and offers Undo (toasts with an action stay until dismissed); "Delete filtered" needs the typed word and also offers Undo. The model filter is built from the runs themselves (`model` and `models`, so ids behind `openrouter/free` are there, and a deleted run's models leave), read in pages in the background. JSON output is re-indented by `prettyJson`, which copies number literals, strings and duplicate keys as written (a parse and stringify would turn `12345678901234567890` and `1e999` into other numbers). The run drawer is an offcanvas: Bootstrap handles Escape only while focus is inside it, so `keepDrawerFocus()` puts focus back after every rebuild (a focused button that is replaced would otherwise leave Escape dead). A live update that arrives while the drawer slides in must not be dropped (`currentRun` is the gate, not the `show` class). Runs seeded as `running` are finalized by the page-start sweep, so specs write them after load. `?tool=` and `?run=` are kept in the address bar.
- **Stats:** works on the daily ledger (`stats.rows`), so its days are **UTC** and it survives pruned history. The whole ledger is read once per load and everything else (range, previous range, this month, today, each key) is derived in memory (`rowsIn`); changing the range reads nothing. Relative ranges (7/30/90 days, this month) are resolved again from the clock on every load (`resolveRange`), and a timer at the next UTC midnight (plus `visibilitychange`) reloads, so a page left open rolls over; a custom range stays as chosen. **Ledger semantics (core):** `StatsRow.runs` and `errors` count on the primary model only, so a run that called several models is one run and one error (the other models gain requests, tokens and cost), and `errors / runs` is a real error rate; `StatsRow.estimatedUsd` is the part of `costUsd` that is an estimate (the whole run's cost when `usage.costEstimated`, plus a booked reservation), shown as `≈` in the KPI (with "Includes $x estimated"), the tables, the chart tooltips and table views. Spend, requests and tokens charts are Chart.js, imported dynamically from `stats-charts.ts` only when there is data to draw, with just BarController/BarElement/CategoryScale/LinearScale/Tooltip registered. Colours are `--or-viz-1..7` and `--or-viz-other` in `_pages.scss` (the data-viz default palette, validated for colour-blind separation and the 7 slots used against the card surfaces of both themes; three light hues are below 3:1, so every chart has a legend, tooltips and a table view as relief). Charts read the tokens at run time and restyle on a `data-bs-theme` or `data-reduced-motion` change (MutationObserver). Series colours follow the entity, not its rank: `assignSlots()` keeps an entity's slot from its all-time rank, so a range change does not repaint survivors; beyond seven series the rest is "Other" (grey), never an eighth hue. Every chart has a text alternative (the canvas's label), a legend that toggles series (none for one series, and then nothing may stay hidden: `pruneHidden`) and a table twin. The tooltip title comes from the active element, not the filtered items, or a day with nothing in it would show the first day's date. Budget, free-today and key balances are always the current month/day, not the chosen range. Page classes that Settings could also use are prefixed (`.or-legend-swatch`, `.or-stats-meter`); small targets meet 24 × 24 px.

## Document tools (Stage 3: OCR, Data extractor, Table extractor)

- **One input component**, `documentInput()` (`src/ui/components/document-input.ts`, range logic in `page-selection.ts`). Nothing is rendered up front: tools call `loadPage(ref)` inside their own pool, so a 200-page PDF never sits in memory as images. At most two PDFs stay open (least recently used idle one is closed and reopened on demand); thumbnails are small JPEGs rendered two at a time, only when their tile scrolls into view, and revoked with their file. The pdf.js and image modules are imported once per page (a cached promise): Vitest never settles concurrent dynamic imports of one mocked module.
- **One run per Run press** (per batch for the Data extractor), requests in `runPool()` (`src/core/pool.ts`, three at a time by default). A failed item is marked on its row and the rest go on; errors that will fail every item (need an action, 401, 402) stop the pool; a run where every item failed ends with the last error, marked presented when the rows already show it. Retrying failed items is a new run that books its own estimate. Output is text only: OCR's combined Markdown, the extractor's JSON, the tables as Markdown; checkpointed as items finish.
- **Structured outputs by catalog flag:** `supported_parameters` with `structured_outputs` → `response_format: json_schema` (strict) plus `provider.require_parameters: true`; with only `response_format` → JSON mode and the schema in the prompt; otherwise the prompt alone. The Data extractor asks once more (bad answer + problem) when an answer is not a usable JSON object. Strict schemas list every property as required; optional fields are nullable.
- **Data extractor values** are normalised on arrival and on every grid edit (`schema.ts`: written numbers such as `1.234,56` or `(12.00)`, ISO dates, choices); doubtful values stay as typed and are flagged, never silently dropped. Exports read the grid's current values. XLSX: currency columns `#,##0.00`, dates as date serials, one sheet per table field keyed by document number.
- **OCR's PDF parser:** `cloudflare-ai` is the free default; `mistral-ocr` is billed per page even with a free model, so free-only mode blocks it with its own notice (the framework's free-only notice never shows for vision tools: a free vision model exists).
## Chat (`src/tools/chat/`)

- **Threads are trees** (`thread.ts`): a node's `parent` is the source of truth, `children` only keeps the order and `selected` the branch shown. Edit and regenerate add siblings; the active path is what is shown, sent and exported. One tool-state key per thread (`thread:<id>`, plus `current`); writes go through one queue. `parseThread` validates and repairs whatever storage returns (orphans, cycles, bad selections, `__proto__` ids), turns a reply left `streaming` into `stopped`, refuses newer versions and reads the linear JSON export. Undo of "Delete from here" re-inserts the removed branch into the thread as it is now (`restoreBranch`), never a snapshot; during a reply it waits for the run to end.
- **Tabs:** each stored change bumps the thread's `rev`; the store announces every write as `tool-state-changed` on the bus, and Chat re-reads that thread (its own writes compare equal and stop there). A tab merges a newer stored version in (`mergeInto`, three-way against `baseOf` what it last read or wrote) when told, or when it finds one while writing; never writes over it. Merge: additions on both sides kept, deletions on both sides stay deleted, a reply keeps its most final version, one streaming here is not touched. Navigation (‹ ›, opening a thread, picking the same model) writes nothing; the `current` pointer is written only when this tab opens, starts or deletes a thread. A thread deleted elsewhere while this tab replies in it is written back.
- **Attachments:** only text files keep their text; image, PDF and audio bytes live in the session map while a message (any branch, any thread, or the composer) refers to them, and an Undo keeps them for its toast. After a reload (or for a model without that input, in earlier messages) they go to the model as a one-line note, and the message says "Attachment not kept after reload". The message being answered is refused instead when the model lacks the input (image, audio, or file for the `native` PDF engine). Text files: 1 MB each, 2 MB per message (Send to as well). The file logic Model arena shares lives in `src/core/attachments/` (kinds, limits, reading, content parts, parser text and `keepParsed`, `approxTokens`, `missingInput`, `parserAddons`) and the chip is `attachmentChip()`; the note in place of bytes gone after a reload stays in Chat (`missingNote`: the shared `toContentPart` returns null without bytes).
- **PDFs are read once:** the turn that sends a PDF to the parser streams like any other; the parser's text comes back in `ChatStreamResult.annotations`, is stored on the attachment (`parsed`), and later turns send it as text: no upload, no parsing, no plugin, and it survives a reload. The engine comes from `src/core/models/pdf-engines.ts`; a paid one is a run add-on (`addons()` for the composer, `beginRun({ addons })` for what a request actually parses, pages counted from the PDF's `/Type /Page` objects or guessed high from its size), so free-only mode and budgets handle it.
- **Limits:** tokens are approximated high (CJK, Hangul, kana, Indic, Thai: 1 per character; other non-Latin: 1 per 2). `max_tokens` is clamped to the model's output cap and to the context left after the prompt; a message that alone does not fit is refused before the run. The estimate is the dearest of the model and its fallbacks.
- **Rendering:** the conversation is `role="region"`, not a live region; `ui.status` announces Reply started/complete/Stopped. Messages redraw only when `messageSignature` changes; a reply that is arriving streams through `streamMarkdown`. The runner's state never rebuilds them: `runner.subscribe` feeds `applyRunState`, which sets `aria-disabled` (focus stays) on buttons that start a run (busy or no model) or change the thread (busy). Focus keys name the place (`regen:<parent>`), so focus survives ‹ ›, Regenerate and Retry.
- **Runs:** every send, edit or regenerate is one run that books an estimate for exactly what is sent (`estimateUsd`), because a chat's own model may differ from the header's, for which alone `ctx.beginRun` would book the tracker's estimate. Messages are committed only after `beginRun` resolves, so a refused run (no key, budget, free-only) leaves the composer as it was; the action is the runner's argument (`ui.runner<Action>`), so the toast's Retry repeats exactly it. An error after the reply started that needs a dialog retries as a Regenerate of that reply instead (the runner's replay would send the message twice). Any other error is shown inline on the reply through `failureText`; one that may have gone through and been billed stores `outcomeUnknown` on the node, shows the caution and a link to OpenRouter's activity, and offers no Retry (Regenerate stays for a user who has checked). The run's `settings` hold the concrete model; `applyState` ignores the model on a `?model=` visit (History's "Re-run with another model").
- **E2E Stop:** the mock cannot stream, so the Stop spec holds the stream open with an in-page `fetch` wrapper. Unit tests `settle()` (runner idle, `kv` unchanged) before the next test resets the database, or a late thread write lands in it.

## Speech-to-text (`src/tools/speech-to-text/`)

- **Input** (`source.ts`): short audio in a format the API reads (mp3, wav, flac, m4a, ogg, webm, aac; at most one part long and 15 MB) is sent as it is. Everything else (long audio, video, other formats) is decoded to 16 kHz mono (`decodeAudio`; ffmpeg's `transcodeAudio` when the browser refuses) and cut at pauses by `splitForTranscription` with `maxSeconds` one below the part length (the planner may add a tail of up to 1 s). Part lengths 1/2/5/8 min: 8 min of 16 kHz WAV is about 20 MB of base64, under the 25 MB body limit most providers have; AssemblyAI is capped at 110 s. Cut parts are kept per source and part length for retries and re-runs.
- **Runs:** two parts in flight through `runItems`. A failed part is never retried automatically (a paid POST that may have billed); its Retry is a new run booking only those parts.
- **Merging** (`transcript.ts`): each part's offset is added and times are clamped to the part. At a seam, words that end one part and start the next (within 2 s of the cut) are dropped from the later part, with their word timestamps; a segment running past the next part's first one is trimmed. Overlaps inside a part are the model's and kept. Speaker labels are per request in the API, so with several parts the keys are `<part>:<label>` and the editor says to give the same person the same name in each part.
- **Model table** (`model-support.ts`): no timestamps for GPT-4o transcribe and MAI-Transcribe 1.5 (docs); speaker labels only through `diarizationRoute`; vocabulary (`keyterms`) is sent only to `deepgram/` and `assemblyai/` (their own APIs take key terms; nothing documents the others, and unsupported means a 400). The vocabulary field is the `tool-prompt` and stays editable; switches the model cannot honour keep the user's choice (`wanted`) and show off and disabled with the reason.
- **Recording:** MediaRecorder (WebM/Opus, else Ogg or MP4) in 1 s slices, 2 h at most; the recording is a session result (leave guard), and replacing one not downloaded asks first. The sample is `sample-speech.mp3` (the 13 KB Kokoro fixture) imported as an asset and fetched on `?sample=1`.
- **E2E:** the microphone is a stubbed `getUserMedia` (oscillator into a `MediaStreamDestination`), so the spec runs in every browser. The 60-minute gate builds its WAV in the page (8 s tone, 2 s silence, repeated) and the mock finds the bursts in each part's WAV and answers with part-relative times.
## Audio tools (Stage 4: Text-to-speech, Music generation)

- **TTS parts:** text is split into about 60 s of speech per part (`chunkLimit`: ~900 characters for Latin scripts, ~300 for CJK, fewer below 1x speed; this also respects Seed Audio's 120 s output cap and the providers' 60 s timeouts) at paragraph, sentence (`Intl.Segmenter`, CJK included), clause, word and only then grapheme boundaries; a paragraph that fits is never split, so 10,000 words is about 125 requests. Parts are asked for as MP3 except PCM-only models (`defaultSpeechFormat`: Gemini TTS), whose PCM is wrapped as WAV at the Content-Type's rate (24 kHz when absent), then joined once with `stitchAudio`. Chromium's `decodeAudioData` honours the LAME header ffmpeg writes, so a joined MP3 decodes to the exact length of its parts (gate: 41.875 s expected and decoded).
- **TTS retries are the user's:** parts that failed or that Stop left unmade stay in memory with the ones made, and "Retry"/"Make the other N" is a new run for just those (`prompt: ''`, so no Recent entry); the tool never retries a part by itself, because a 5xx may already have billed. Voice previews are runs too (`prompt: ''`), cached per model, voice and speed as object URLs for the session.
- **TTS speed** shows only for model families known to take it (`SPEED_MODELS`: Seed Audio, Voxtral, Kokoro; Kokoro unverified through OpenRouter): the catalog lists no parameters for speech models. Voice cloning (`input_references`) is not offered.
- **Music variations** are one run with one streamed request each (`runItems`, all at once): one History entry and one budget decision, the estimate is the flat price times the count (so three Clips, $0.12, open the default $0.10 per-run confirmation). The Clip/Song radios write the tool's model binding (`setToolBinding`) and are disabled during a `?model=` visit. A target length is cut with `trimMedia` (2 s fade, 192 kbit/s like Lyria's MP3s); a failed or stopped cut keeps the paid song whole. Pro's timed lyrics carry only start times: a line ends at the next line's start unless a section marker comes between (an instrumental passage may follow), then after the song's median line gap.
- **E2E:** the 10,000-word TTS estimate (about $0.25 at Kokoro's priciest endpoint) opens the budget confirmation, which the gate accepts.

## Image tools (Stage 5: Image generation, Image editor)

- **`POST /images` only** (the chat route needs $1 of key balance, docs/openrouter-api.md §0). What a model takes comes from `GET /images/models` through `imageModelControls()` (`src/core/models/image-params.ts`); a field it does not list is never sent (a 400). Forms keep what the user asked for and send only what the current model takes, so a model switch loses no choice. One policy for every image tool, `models.imageControls(id)`: listed → `ready`; read but not listed → `missing` (refuse before the run); unreadable or empty → `unknown` (bare controls, only the prompt is sent: let the request try). A failed read is retried after 30 s and after `models-refreshed`, never latched for the visit. A zero catalog image price is unknown, not free (`estimateImage` returns null).
- **Several images:** one request with `n` when the model's `n.max > 1`, else one request per image (`runItems`, three at a time) with `seed + i`, or a locked seed would repeat one picture. The run's seed is drawn before `beginRun` but written to the field only after it (a refused run changes nothing).
- **Masked edits:** there is no mask parameter, so `input_references` are [the picture with the mask tinted magenta at 50% (`maskOverlay`), the plain picture, the mask as a black/white PNG], cut to the model's `input_references.max` in that order, with an instruction naming each reference; `aspect_ratio` is the offered one closest to the canvas and `output_format` PNG when offered. References are built from the decoded, upright pixels at one common size (<= 2048 px), and the instruction names only the references actually sent. A result of another aspect is fitted and centred (never stretched) with a warning. "Keep outside the mask" composites the result through `featherInside(mask)`: a box blur clamped to the mask, so outside pixels are the original exactly and only the inner edge blends (gate: 0 differing channels outside). Outpaint places the picture on a grey canvas and the new area is the mask; there the soft edge sits on the picture's side of the seam, so the grey filler never blends into generated pixels. While an edit runs, loading, version changes and painting wait; only the version on screen stays decoded, and pictures over 16.7 MP are scaled down on load (compositing stays full size).
- **Mask undo** replays strokes from blank (`replayOps`), no snapshots; after an inpaint version the mask is cleared as one undoable step. Versions are session results created with `imageResultCard({ viewer: false })` (the canvas shows the picture); only the working version's card is in the page.
- **Received files wait for the model's limits** (`?receive=` is applied right after `setup`, before `/images/models` answers), or references would be refused as "no room".
- **`.vstack` inside a tool's input zone grows:** Bootstrap gives it `flex: 1 1 auto`, and the input card body is a flex column stretched to the output's height, so a `vstack` child opens a gap when the output is taller. Use `d-flex flex-column` for direct children of `ui.input`.
## Isolated image (`src/tools/isolated-image/`)

- **Adaptive threshold** (`adaptThreshold`/`adaptiveThreshold` in `src/core/media/image-pipeline.ts`): edit models answer on off-white (240-252) with noise, and at a fixed 245 that noise counts as content: the product box becomes the whole picture and grey specks survive the fill. The background is the **lightest** population on the picture's border (around its 90th percentile, read twice), never the border's median: a pale product covering most of the frame once lowered the threshold to its own value and was erased while the QA passed (review finding). The threshold is kept 7 median absolute deviations plus 3 below that background (about 6σ of Gaussian noise), so neither the noise nor a soft shadow's faint tail crosses it (the second gate run caught that tail at 245 on a 250 background), and 3 above the lightest of any darker population on the border (a product reaching the frame stays content). A clean background (flat 251 and up) keeps 245. When the background holds under a quarter of the border, is darker than 200, or overlaps a pale product, the fixed threshold is used and `backgroundUnclear` fails the QA ("check this one"). Automatic is the default per photo; a threshold set in the review is used exactly.
- **Despeckle** (`despeckle`/`fillAndDespeckle`, same module): where a soft shadow fades through the threshold inside noise, the edge fill leaves a band of grey specks that widen the product box and stay as dots (the first gate run caught it on a 250 background). With the option the background is filled on the model's picture first; the pixels it did not reach are grouped through corners too (8-neighbour: a diagonal line is one group, and one with the product it leaves), and only a **speck** becomes white: at most 64 pixels, at most 12 long and three times as long as wide, nothing more than 40 below the threshold, no such darker pixel within 3 px, off the picture's edge. Then the box is found. A share-of-the-picture limit (the first version) erased 1-px diagonal lines, threads and beads (review finding); fixed small limits do not, because noise specks do not grow with the picture.
- **JPG border:** JPEG codes 16 x 16 blocks and the decoder smooths chroma across them, so a block holding product tints its border pixels: at 2000 px with a 0.5% margin the exported JPG had 35 grey border pixels while the QA (on the pixels before encoding) passed (review finding). A JPG keeps at least `MIN_JPG_MARGIN_PX` (24) of white (`appliedMargin`; the review shows "0.5% (JPG uses 1.2%)"), and every exported JPG is decoded again and its border counted (`encodedBorderFlaws`), which the QA reports. PNG keeps any margin.
- **QA** is `checkIsolated` on the square (border exactly #FFFFFF, product off its edge) **plus** the product box against the model's picture edges (`qa.ts`): with any margin the padding alone makes the first check pass, so the box reaching the picture's edge is what catches a product cut off by the frame, or a background that was not white (box on all four edges).
- **Results always follow the current settings:** each photo keeps the model's answer (`edited`, paid for); `processingKey` (size, margin, threshold and whether automatic, sharpening, format, JPG quality) tells when its result is stale, and `reconcile()` makes it again in the worker (two jobs in flight, a newer job supersedes an older one), never with a request. Review controls, settings changes, a run's end and a Stop between a paid answer and its result all go through it. A result is named when it is committed, under the pattern of that moment and the format and size of its Blob, so one finishing after a pattern change gets the new name; a later pattern change renames (a new card for the same Blob, keeping "downloaded").
- **Result cards** are the framework's `imageResultCard` (leave guard, download, Send to…, Remove with focus handling), with `viewer: false` and this tool's thumbnail, badges and QA reasons in its `extra` part, redrawn in place; Review, Edit again and Another model are its `actions`. Only the file as it is is offered (`formats: []`): its JPG border was checked after encoding, a canvas conversion's would not be. Remove drops the photo (asking first when its result was not downloaded). The photo list and the grid show `imageThumbnail` copies (144 px for the list, 288 px for cards about 250 px wide), never the 2000 px result, and a photo's change redraws only its own row and card.
- **Promptless** (`promptless: true`): the instruction is fixed, so the tool takes no notes; a note could only weaken "keep the product unchanged, remove everything else" (and an earlier notes field did nothing the settings could not). Prompts saves settings presets; History keeps the settings and one QA line per photo.
- **Runs:** Isolate sends only photos without a result; Retry and "Another model…" are new runs for those photos (`runner.trigger({ keys, model })`, booking that model's estimate); a new answer resets the photo's review choices. The error toast's Retry goes through `replayArg` with `pendingOnly`: it skips photos the failed run made (`editRun` is the latest run's id), so a 402 mid-retry never pays twice, while "Edit again" on a photo with an older result still sends it. What a model takes comes from `ctx.models.imageControls`: `n: 1` and `output_format: 'png'` only when its controls list them; `missing`, or no range allowing one reference, is refused before the run; `unknown` (the list could not be read) sends the photo and the instruction only. The estimate is one edit per photo, each uploading its photo once (`references: 1`, `requests`), the answer as large as the largest photo sent (`readImageSize` reads the header, nothing is decoded).
- **Review:** the before/after wipe (`compareSlider`) compares the original upload (letterboxed) with the result, so the product does not line up (the model reframes it); side by side is the view for checking logos and text. Its margin range follows the setting while the photo has none of its own (0.5% steps, like the setting), Previous/Next are recomputed whenever results change, and a verdict that turns or a result being made again is announced politely; the run's last status names what failed (two at most).
- **E2E gate:** photos and isolations are drawn in Node (`tests/e2e/isolated-image-photos.ts`, with its own PNG encoder); the mock finds a request's photo by its data URL, because photos under 1024 px and 4 MB pass through `toDataUrl` untouched. The exported JPGs are decoded in the page and checked pixel by pixel.

## Video studio (`src/tools/video-studio/`)

- **One clip = one run = one persisted job.** Generate (and every sequence step) begins a run with the form as it was when pressed (model, prompt and settings snapshot), sends `POST /videos`, adds the job (state `running`) and `run.handOff(job.id)`s at once, so Generate is free again and leaving is safe. The `video` job handler only polls (quickly at first, slowing to the documented 30 s, `pollInterval`) and succeeds with the completed status's cost as `usage`, which the core books on the run before the job turns final; the video is downloaded at delivery, not in the poll. Whichever tab sees a job final delivers it once: `runs.reattach` ends the run, the clip is placed and its sequence step settled in ONE locked store step (`delivery.ts`, idempotent: a repeat finds the clip and settles the step again; `repairSlots` does the same on load), and the job's payload is marked `delivered` (so a clip the user removed never comes back). A download answered 404 marks the clip `expired` (cost stays booked; never offered, joined or fetched again). A remote failure is recorded as an `OrError`, never a bare Error (History would read "Something went wrong"); "Stop waiting" ends the run with `run.cancel()` (aborted at once, booking the reservation). No video request is ever sent again by itself: one the API client marks `outcomeUnknown` gets the framework's toast without Retry (its default OpenRouter activity link is the right check: a POST without an answer has no job id to look up), one OpenRouter accepted that the page cannot follow (no job id, the job not stored) is shown by the tool without Retry (`markSent`), and the runner's Retry always repeats a clip (`replayArg`), whatever tab shows by then.
- **Persisted state** (`store.ts`): the timeline and the sequence run are JSON in `ctx.state`, changed only by read-modify-write under one Web Lock (`ortoolbox:video-studio:state`), and every tab re-reads on `tool-state-changed`. Videos are memory-only: after a reload generated clips are downloaded again while OpenRouter keeps them (retention is only known to be >= 18 min); uploads are listed as "add it again". `forget()` aborts a clip's download and nothing of a removed clip is kept or registered again.
- **Form edits reach the stored run field by field** (`SpecEdit`, `applySpecEdit`): only the fields this tab's user changed (a prompt or role per step, style, cap, failure rule, a step's image count), typing debounced and flushed before Start, Resume, Re-run and blocker answers. Every change of the stored run (here or in another tab) is read back into the form with this tab's unwritten edits on top, so a stale form never writes over the run (a cap lowered elsewhere is not raised back). While a sequence is running its prompts, roles and style are read-only (a step being sent reads them); cap and failure rule stay editable. Image counts follow what the user sets, so removing images on purpose is allowed; a step with fewer pictures than its count (lost in a reload) pauses with an `images-lost` blocker.
- **Sequences:** `sequence.ts` holds the pure rules, `sequence-runner.ts` the side effects (injected dependencies, unit-tested with an in-memory store). `plan()` decides what starts (chained one at a time, independent 3 at once) and stops before a step that would pass the spend cap; spent means billed or maybe billed (a known cost, else the reservation of an unknown cost, an `outcomeUnknown` or accepted-but-untracked send, an abandoned start, a "Stop waiting", a job the core gave up on; shown with "≈"), the same as the run books, so a job the provider failed (`failureKind: 'remote'`) counts nothing. Slots are claimed under the lock with the claiming tab's id (each tab holds a life lock `ortoolbox:video-studio:tab:<id>`), and the start re-reads the stored run after every await: Pause, Stop, another tab or the cap hand the claim back with nothing sent (`returnClaim`; `releaseClaim` for errors never turns stopped into paused), and Pause/Stop abort a start in progress (budget dialog included). A failed start follows the failure rule; errors that need the user (no key, locked, free-only, budget) pause and are presented. A chained step whose clip to continue is gone (removed, a lost upload, expired) is never sent from its prompt alone: a `source-missing` blocker offers another clip, no first frame (`chooseSource`), or a re-run of the step before. Each Re-run is a new `attempt` carried by its job, so a late job of an old attempt never settles the new one; its take replaces the old in place (left out of the join) and the chained clip after it is marked `staleSource` (its first frame is no longer dropped; the step shows "re-run it"). `recover` (page load, bus changes, becoming visible) settles slots `starting` whose claiming tab is gone: adopts their job, else fails them as maybe billed and pauses. A last frame alone (no first frame) is refused (`LAST_FRAME_ONLY_MODELS` is empty).
- **Frames win over references** (API: with both, frames are used): the form shows only the inputs of the chosen mode, and a chained step that starts from a frame can take only a last frame. Continue captures the true final frame (`captureFrame('last')`) as a PNG data URL (kept as PNG when under 4 MB); the clip goes right after its source with "leave out its first frame" on. Native extend sends a public `https://` link as a `video_url` reference only to models priced "with video input" (Seedance); otherwise it falls back to Continue and says why. `PREVIOUS_JOB_MODELS` is empty: grok and Seedance mini reject `previous_job_id`, and no model is confirmed to take it.
- **Budgets (owner decision):** a sequence asks ONE question at Start for its total estimate (every step x repeat, the cap shown; `budgets.check` with the total, the tool's own dialog; a block throws `BudgetBlockedError`), and a declined Start stores and sends nothing. Its steps then begin their runs without dialogs of their own, each still reserving its own estimate: the tool wraps the shell's handler (`ctx.runs.setConfirmHandler`, delegating to `budgetConfirm`) and approves runs whose `groupId` is a sequence whose non-forced step is beginning. A Re-run asks for itself. Start refuses to overwrite an active stored run (another tab's). Estimates add Grok's per-image input price for frames and references (`estimateVideo` `images`).
- **Rendering and focus:** the timeline is rebuilt only when its signature changes (a rebuild moves the `<video>` players, which pauses them), and the source selects only when their options change (a rebuild closes an open list); only usable clips are offered as sources. Reorder buttons at the ends are `aria-disabled` (focus stays after a move; the clip's name is announced); trims always show the stored, clamped value with `aria-invalid` and a note. Join moves focus to Stop and back; the frame grabber returns focus to its opener and steps by the clip's own frame rate (`video-fps.ts` reads the MP4/MOV `mdhd` and `stts`; 30 fps otherwise), its last position being the true final frame. Product code finds controls by focus key or reference, never by `data-testid`. The join runs `concatVideos` (multi-threaded when the page is isolated; it refuses more than `MAX_JOIN_BYTES`) with its own Stop; the core's download progress keeps arriving after a Stop and is ignored. A joined video is a `videoResultCard` (`covers` its clips, so its download counts them as saved). Notifications follow the drawer switch: a one-clip job passes it as `jobs.add` `notify`; sequence steps pass false and the tool shows one notification when the sequence ends (the core's `'group'` would fire after the first chained step, which has no open job after it).

## Model arena (`src/tools/model-arena/`)

- **The contenders are the models:** the manifest says `"ownModels": true`, so the header has no model chip (it would name a model the arena does not use) and no free-only substitution note; Run is still disabled when free-only leaves no text model at all. The form (2–4 contenders, system prompt, temperature, Max tokens, blind, PDF reader) is the snapshot and is also kept in the tool's options; a first visit picks distinct free text models (preferred defaults first, then the newest free model of each other provider; paid ones only to reach two). Files are not in the snapshot (bytes stay in memory).
- **A round:** every contender's run is begun in parallel (`groupId` = the round's id, so one budget dialog), each with its own estimate and PDF parser add-on; the round starts only once every `beginRun` answered, so a round refused as a whole changes nothing, and all requests then go out together (fair time to first token, measured from just before `chatStream` to the first text or reasoning token). A contender refused alone (a partial budget block) shows the reason with Retry. Missing inputs, a prompt too long for a model, and free-only (all contenders and the parser together) refuse the round before anything is booked. The round's input, settings snapshot and files are taken when Compare is pressed (`input()`), never after the planning or the budget dialog: a file dropped meanwhile belongs to the next round. Max tokens is clamped per model (`fitOutput`: output cap, room left in the context) and is what estimates assume; unset, nothing is sent and estimates assume the model's cap, at most 4,096. The prompt's tokens are counted once per refresh and passed to every contender's request. Retry is the runner's argument `{ kind: 'retry', index }`: a new run in the same group, with the round's own input (the files are kept while the round is on screen); from the press until it settles `round.retrying` closes voting and export (`allIn`). Every contender's request parses a new PDF, so a paid reader is charged per contender; the parser text then rides on the shared `AttachmentRef`, and later rounds send it as text.
- **Blind (default):** panels are shuffled (`order`), labelled Model A–D, and nothing that tells models apart is drawn before a vote or "Reveal without voting": no names, no cost ($0 gives free models away), no "Cheapest", no panel letter in History (`run.finish` writes no meta), errors with every form of the model's name replaced (`blindTerms`: id with and without variant, last segment, provider, name with and without prefix or "(free)"; case-insensitive, whole words), and one neutral billing note on every failed panel instead of the paid-only "may have gone through" (shown after the reveal). A blind round revealed by hand takes no vote (it would not be blind). Speed metrics and "Fastest" show at once. Export is offered once names show and every answer is in (`exportReady`); its Markdown closes code fences an answer left open. Metrics: token counts come only from the stream's usage chunk (a stopped or cut stream shows "—", though the client books zeros); tokens/s needs at least 50 ms after the first token and is dropped when the count includes reasoning that never streamed; a full tie marks neither "Fastest" nor "Cheapest"; `finish_reason` "length" is marked as cut off.
- **Tally:** `tally` in the tool's state, read-modify-write under the Web Lock `ortoolbox:model-arena:tally`; a model counts once per voted round in which it answered (rounds, wins, ties, "all bad"). Undo of Reset adds the old counts to whatever was voted since.
- **`?model=` (History's "Re-run with another model"):** each contender run's settings hold the whole round, so the round reopens and the override replaces the contender whose run was opened (setup reads the `?run=` record before the framework's `applyState`); without a round of this tool, it replaces contender 1. Either way it is saved like any other form change and kept for the next visit.
- **Rendering:** panels are built once per round and updated in place (the stream owns the answer); a panel's error block is rebuilt only when the error changes, so a focused Retry survives other contenders finishing; the comparison and tally tables keep their scroll regions and redraw only their rows (focus and scroll stay). The answer is a focusable, scrolling region (28rem) so four long answers stay side by side.
- **E2E concurrency proof:** the mock answers SSE in one piece, so the gate spec holds every chat `fetch` in the page until four are waiting; a round that sent them one by one would never get past the first.

## Decision (`src/tools/decision/`)

- **Two pure modules decide everything that matters:** `schema.ts` (the form's data, validation, the request) and `results.ts` (reading a response, confidence, the verdict, percentages); the builder, situation panel, library and results view only draw them. A `QuestionDef` is flat: it holds a question's Yes/No criteria, options and levels at once, and `wireQuestion` sends only the active type's, so switching a question's type loses nothing the user typed (the image tools' policy for model parameters).
- **Ids are slugs, and three keys are not allowed.** The id on the wire is `slugify(name)`, made unique (`name_2`), and follows the name until the user edits it (emptying it hands it back). `wireId()` (id without surrounding spaces) names a question in the request, the validation and the answer lookup, and the builder's `toDef` trims it too: an id typed with a trailing space and run before it lost focus still finds its answer. The API client reads every response through `parseJsonSafe`, which deletes `__proto__`, `constructor` and `prototype` keys at any depth, so an answer filed under such an id, or a probability under such an option name, would never arrive: `uniqueId` skips them and validation refuses them.
- **Confidence has three sources.** Yes/No (`noul` is P(yes)) has none on the wire, so it is `max(p, 1 - p)`; Choice and Score use the API's `confidence`, else the highest probability, else nothing, and an answer with no confidence is never "Clear". The Mercury and Jev shapes differ in key order and rounding; `results.ts` never depends on order, ignores unknown keys, answers for ids nobody asked and `type` fields it does not need, and turns a missing or unreadable answer into a `none` card instead of throwing.
- **The badge is decided on the number that is shown.** `formatPercent` cuts (not rounds) to a tenth of a percent (83.9%, never 84%), and `verdictOf` compares those same whole tenths against the threshold, both with a noise-sized epsilon (1e-9 on `p * 1000`: `1 - 0.07` is 0.9299999999999999, which an exact comparison put below 93% beside a card saying "93%"; 0.9999999995 must not read "100%"). A test sweeps every tenth against every integer threshold. A threshold change edits the shown badges in place (`ResultsView.relabel`), so nothing redraws and no fill animates again; nothing is sent. Cards are matched to thresholds by the builder row's key (`builder.keys()`/`thresholds()`), not by id, so a rename after a run keeps the card attached, and `run` relabels after `show()` for a threshold edited while the request was out.
- **Two token numbers for two jobs** (`tokens.ts`, over `approxTokens` from `src/core/tokens`). The price estimate inflates the whole body by 2.5 (Jev billed 476 input tokens for the 830 characters of the tutorial request, Mercury 253). The context check, which refuses a request before `beginRun`, counts the situation's prose as prose and inflates only the structure around it (questions, field names), so about 120,000 characters of text still fit a 32,000 token context; a refusal must not lean high the way a price does. The context is the catalog's `contextLength`, else 32,000; the numbers go in the status and an alert under the form.
- **Problems show only for fields the user touched** (changed, or named by a failed Run), so a fresh card is not scolded for being empty; `showProblem` leaves a message that is already on show alone (an unchanged message would be announced again), the first problem takes focus and the rest are marked. Situation is checked before Questions.
- **The snapshot's `prompt` is what is sent:** the text block in text mode, the `name: value` lines of the fields in fields mode (`promptOf`), so Prompts' Save current has something to save and History, search and Recent describe the run. `settings` = `stateMode`, `fields` (rows as typed, blanks included), `questions`, and in fields mode `text`, the text block kept behind the fields (never sent, so not the prompt). `applyState` takes the fields and that text from the settings in fields mode and the prompt as the text in text mode, and leaves the questions or the fields alone when the snapshot has none. Lists the user emptied (options, levels) stay empty on the way back; validation flags them. A drop or send that adds nothing (every file over 1 MB or empty) changes nothing, not even the mode. The run's output is `JSON.stringify(response.answers)` (History re-indents); the Download/Copy file is `{ model, answeredBy, state, questions, answers, usage }` of the last run.
- **Saved deciders are one tool-state key each** (`decider:<uuid>`), never one array, so two tabs cannot overwrite each other's; Undo of a delete writes back the same record under its old id; the list follows `tool-state-changed`. Choosing in the list loads nothing (arrowing through a closed select would): the Load button does, and asks when it would lose something (`lossOnLoad`): the questions differ from what was last loaded or saved (`baseline`, a JSON snapshot), or the decider brings a situation that replaces a different one in the form. Saving the situation is opt-in (default off: it can be private text), and a name already used asks before replacing.
- **The scale reorders three ways, one of them a pointer.** HTML5 drag from an `aria-hidden`, untabbable handle (its payload has a type of its own, never `text/plain`, which a text field would take in; a drop clears the drag itself, because the redraw removes the dragged node and its `dragend` may never come, and focus goes to the level that moved); Move up/down buttons (the accessible route, which also keep focus on the moved level and fall back to its twin at either end). Levels are numbered from 0 like the API's `score`, which is a position on the scale (1.99 sits near level 2), drawn as a marker with one tick per level; every probability is also text, and the drawings are `aria-hidden` (the scale is one `role="img"` with a full label).
- **Fills animate with `transform: scaleX(var(--or-fill))`**, set after two frames; `_motion.scss` already zeroes transitions under the OS preference and the Reduced motion setting, so no code asks.
- **The model picker's help text** lives in `CAPABILITY_INFO.decisions.help` (Jev and Mercury Decide are the only models verified to accept this schema). Free-only resolves to `inception/mercury-decide:free` from the shipped defaults.

## Bot-to-bot chat (`src/tools/bot-to-bot/`)

- **One run per press:** each Start, Resume or Step is one run (`models: [A, B]`, `groupId` = the conversation's id), booked at min(cost cap minus spent, per-turn estimate × turns left); the per-turn estimate assumes every turn uses Max tokens and the prompt grows by one full reply per turn (an unknown price books the cap left). With the default $0.25 cap a paid Start is above the $0.10 per-run threshold, so Warn mode confirms it: that is intended. The run checkpoints the Markdown transcript after every turn and finishes with it (History's replay). Everything is checked before `beginRun` (opener, distinct names, the limits, the other tab), so a refused run changes nothing. A run's names, personas and models are fixed when it starts; the limits are read live (raising one while paused lets Resume go on). Pause pressed before the loop starts still holds after the first turn; it is cleared when the runner goes idle.
- **Stop conditions** live in `loop.ts` (pure, fake-timer tested). After a turn: cut by time, stop phrase, cost, turns, time; before one: turns, time, cost (spent plus the next turn's estimate; an unknown estimate skips that check). The cap counts as reached only once something was spent, so a $0 cap still runs free models. The time limit is a timer aborting the turn's own signal (`chatStream`'s `signal`, combined with the run's by the client), so the partial text is kept as `cut`; Stop aborts the run's signal and ends the conversation (`stopped`), while an abort from elsewhere (pagehide) only holds it. A turn's own usage comes from a `Proxy` over the run handle that tees `addUsage`; an unknown cost counts as that turn's estimate.
- **Messages per speaker** (`request.ts`): own turns are `assistant`, the other bot's and the moderator's `user`; moderator text (the opener too) is marked `[Moderator]`, and inside a merged user message every part is labelled (`[Bot A] …`), or the bot cannot tell who said what. Trimming drops the oldest entries after the opener (framing and opener always stay) and records `trimmed` on the turn. Failed turns are a record only (not sent, not counted, the same bot speaks again; empty ones are dropped on Resume); end markers stay where they were, and a Resume carries on after them. Editing removes everything after the entry (Undo only while the edited entry is still last and unchanged); an edited cut turn counts as finished.
- **Persistence and tabs:** one conversation in tool state (`conversation`, `rev` per write, copies written through one queue). A turn left `streaming` by a reload keeps its text as `stopped` (or goes when empty), so it comes back paused. The running tab holds the Web Lock `ortoolbox:bot-to-bot:<id>` (a second tab's Start/Resume is refused); a tab that is idle with no writes pending follows a newer stored version or a delete, and a running tab's writes win (moderate in the tab that runs it).
- **Run bar:** the runner's own button is hidden; Start/Resume and Step, or Pause and the runner's Stop, take its place in the bar, and Ctrl/Cmd+Enter (no argument) is Start or Resume. A focused control that hides hands focus to the one that took its place (`fixBarFocus`, run synchronously from the runner's subscription while the hidden button still has focus). On a `?model=` visit `applyState` gives Bot A the visit's model (A follows `ctx.model()`); B keeps its own. The manifest says `"ownModels": true` (no header chip): each bot has its own picker, and a bot without one uses the tool's default text model.

## Non-obvious decisions

- **Service worker = offline shell + cross-origin isolation.** GitHub Pages cannot send headers, so the one service worker (`src/sw/sw.ts`) adds COOP `same-origin`, COEP `require-corp` and CORP `same-origin` to every same-origin response it serves (needed for multi-threaded ffmpeg.wasm). Always `require-corp`: nothing is hot-linked, so `credentialless` would buy nothing and needs per-browser negotiation. It never calls `respondWith` for cross-origin requests: OpenRouter calls go straight from the page.
  - **Isolation reload is opt-in:** `boot({ isolation: 'required' })` (Diagnostics and Video studio only) reloads once at page start on a first visit, guarded by sessionStorage `ortoolbox:isolation-reload` so it can never loop. Every other page only registers the worker and must never reload (the OAuth callback carries a single-use code); the next page the user opens is isolated anyway. Without isolation, ffmpeg runs single-threaded.
  - **Caches** (all named `ortoolbox-…`, because every project site on `ethanpil.github.io` shares one CacheStorage): `pages-<build hash>` holds the HTML and un-hashed public files, each verified against a SHA-256 recorded at build time (a stale CDN copy fails the install, which the browser retries later; a failed install deletes only its own incomplete cache). `assets` is shared by all builds: every page's eager closure (from Vite's build manifest) is added at install, lazy chunks and `vendor/` files on first request; entries unused for 60 days are pruned. So a tab opened before a deploy can still lazy-load chunks it fetched before. Range requests bypass the cache; every cache call in the fetch path falls back to the network.
  - **Updates:** a new worker `skipWaiting()`s and claims open pages without reloading them; the next page load gets the new shell. Activation deletes only complete pages caches of *older* installs.
- **Shared origin.** For the same reason, localStorage, IndexedDB and sessionStorage are readable by any other page under `https://ethanpil.github.io/`. Keys at rest there are only as safe as every other project site on that origin; a custom domain removes the risk.
- **ffmpeg loading (`src/core/media/ffmpeg.ts`).** `@ffmpeg/ffmpeg` always starts a *module* worker, so we ship the cores' ESM builds, self-hosted under `vendor/ffmpeg/core[-mt]-<version>/` (copied from node_modules by `vite-plugins/ffmpeg-assets.ts`, served by middleware in dev; versioned URLs are immutable). The page downloads the wasm itself (progress against the size recorded at build time, because Content-Length is the gzipped size on Pages) and hands it over as a `blob:` URL; core JS and workers load from same-origin URLs, so no `blob:` worker or script is needed. `optimizeDeps.exclude: ['@ffmpeg/ffmpeg']` is required for its worker URL to survive the dev server. Core start-up has a 60 s timeout; if the multi-threaded core fails or times out, the page uses the single-threaded one for the rest of the session. Terminated or crashed instances are never handed out again; `disposeFfmpeg()` frees everything. ffmpeg's file system lives in its worker, not in the wasm heap, and Chromium cannot allocate one 2 GiB buffer: joins are capped at `MAX_JOIN_BYTES` (1.5 GiB, peak about twice the result).
- **CSP** (`vite-plugins/csp.ts`, the single source, with a reason per directive): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self' https://openrouter.ai blob: data:; img-src 'self' blob: data:; media-src 'self' blob: data:; style-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-src 'none'; form-action 'self'`. Tighter than PLAN.md: no `blob:` workers, no frames, no remote images or media (results arrive as base64 or are fetched from openrouter.ai into Blobs), no form posts to OpenRouter (sign-in is a navigation). `'wasm-unsafe-eval'` is measured as *not* needed by ffmpeg in Chromium/WebKit (wasm compiles inside network-loaded workers, which do not inherit a meta CSP) but is kept for Firefox (unverified) and main-thread wasm (pdf.js fallbacks); it allows wasm compilation, not JS eval. No `'unsafe-inline'` for styles: Bootstrap/Popper set styles through the CSSOM, which CSP does not restrict. `build.assetsInlineLimit: 0` stops Vite inlining fonts as `data:` URLs (would violate `font-src`).
- **Dev parity:** the dev server gets a CSP meta tag from the same table plus only what HMR needs (`'unsafe-inline'` styles, the HMR `ws:` origin), and sends COOP/COEP/CORP via `server.headers` (and from the ffmpeg middleware), so dev pages are isolated without the worker and CSP violations show up in `e2e:dev`. `vite preview` sends no headers, like Pages. Specs that differ between the two read `isDevServer()`.
- **Theme before first paint:** `public/theme-init.js`, a classic render-blocking script (inline scripts are forbidden), reads `appearance.theme` (`light`/`dark`/`system`) from localStorage `ortoolbox:settings` and sets `data-bs-theme`, then follows OS changes while the theme is `system`. It is the one sanctioned storage read outside `src/core`; keep its contract in sync with the settings schema. The View Transitions opt-in is CSS (`@view-transition` in main.scss), not a meta tag.
- **Sass:** Bootstrap and Bootstrap Icons are loaded with `@use … with (…)`, not `@import`, so our own code has no deprecation warnings; `quietDeps` hides the ones inside Bootstrap (import, global-builtin, color-functions, if-function). The icon font URL is overridden in main.scss because the package builds it from variables, which Vite cannot resolve.
- **TypeScript 6, one compiler.** `typescript` is pinned to 6.x for tsc, ESLint, Vite and Vitest alike, because typescript-eslint does not support TS 7 yet (TS 7 ships no JS compiler API). Revisit when it does.
- **Remote media is fetched, not hot-linked.** Under COEP `require-corp` cross-origin `<img>`/`<video>` without CORP are blocked, and the CSP forbids them anyway. Load results with `fetch` → Blob → object URL. `connect-src` allows only openrouter.ai: if a result ever lives on another host (`unsigned_urls` may), use the openrouter.ai content endpoint or grow the CSP deliberately.
- **OpenRouter CORS** (checked 2026-10-02): `Access-Control-Expose-Headers` is only `X-Generation-Id,X-Provider-Name,request-id,cf-ray`, so browser code cannot read `Retry-After`; back off without it. The mock reproduces these headers.
- **Core services are factories** (`createApiClient(core)`, `createKeysService(core)`, …) that read other services from `core` at call time, never in the factory body, so the composition root can wire circular dependencies. Tests pass a partial core (`testCore()` in `src/core/api/test-fakes.ts`: real bus and settings, under `isolateChannels()`).
- **API client rules** (`src/core/api/client.ts`): keyless catalog GETs send no custom header (no preflight). **A retry must never pay twice:** idempotent GETs retry 408/429/5xx/network failures; paid POSTs only 429, the in-flight 402 and 503 (OpenRouter certainly did not start them); chat only 429 and the in-flight 402; never a stream once its response started, never the auth-code exchange (`mayRetry`, `RETRY RULES`). Waits honour `error.metadata.retry_after_seconds`. A paid request that may have reached a provider without a known cost (network loss, abort, stream without a usage chunk) reports `costUnknown`, so the run books its reservation. `:free` requests are throttled to 20 per rolling minute through localStorage `ortoolbox:free-requests` plus an in-memory window (shared across tabs, approximate; a broken store never resets it). A `noRetention` key adds `provider.data_collection:"deny"` unless every model of the request is free (it turns free ones into a 404), never on `/images` or `/videos`. TTS bytes carry no cost, so usage is estimated from the most expensive endpoint (`costEstimated`, or `costUnknown` without endpoint prices); video cost arrives only on the completed status read (`VideoJobStatus.costUsd`), which the job's `succeeded` result carries as `usage`. Paid and chat POSTs (not all-free) that lose the connection after sending, or get a 408 or a 5xx other than 503, throw with `outcomeUnknown`: `presentError` and the runner offer the tool's `safeAction` (or OpenRouter's activity page) instead of Retry.
- **Key lock:** every lock change rewrites `ortoolbox:keys` with one `setItem` and is refused (`KeysChangedError`) if another tab wrote meanwhile; backup and reset use `keys.exportFile/replaceFile/clear`, never the storage key. sessionStorage `ortoolbox:unlocked` holds `{key, at}` (raw AES key, last `touch()`), so auto-lock (capped at 24 h, re-armed when the setting changes) survives navigation between pages of one tab; a session key that no longer opens `lock.verifier` is dropped at page start and before encrypting. The first key added becomes `settings.defaultKeyId`; a null or stale id falls back to the first key. Removing keys also removes settings that point at them (default, tool bindings, per-key budgets). OAuth refuses with KeyLockedError before consuming the code, so the callback page unlocks and retries.
- **Models:** capabilities and free detection follow docs/openrouter-api.md §9 (free = id only; music = Lyria). Caches are stale-while-revalidate (one background attempt, a failure remembered for 5 minutes) and dropped on `data-reset`. `ModelPricing.prompt/completion` are null for non-token units (TTS, STT, video, music); estimates read `pricing.raw` and endpoint prices with deliberately high heuristics (`src/core/models/estimate.ts`). Shipped defaults and their reasons live in `src/core/models/defaults.ts`; re-check them when the catalog moves. `resolve(tool, cap)` applies the run override (`?model=`) and the tool binding only when `cap` is the tool's primary capability (`capabilities[0]`): a text model pinned on Chat must not become its vision model.
- **Media gotchas:** never use fflate's async API (`zip`, `unzip`, `deflate`): it spawns `blob:` workers that `worker-src 'self'` blocks, and fflate then never settles. Use `zipSync` or `zipFiles()` from `src/core/export`. Multi-threaded ffmpeg crashes on H.264 encodes with the default thread count; every `exec` must pass explicit `-threads` limits (see `src/core/media/ffmpeg-ops.ts`). Import `src/core/media/pdf.ts` dynamically only (about 5 MB of pdf.js assets). Stitch TTS/audio segments with `stitchAudio()` (decode → PCM → encode once; `concatMp3` leaves seam gaps). Run heavy pixel work in the image worker (`isolateImage`, `maskOverlayAsync`, `maskToRasterAsync`, `featherInsideAsync`, `compositeMaskedAsync`; module worker, falls back to the page), never the pure raster functions on the main thread; the source is not transferred while a page fallback may still need it, and a failed worker is recreated (the page takes over after three failures in a row); decode and encode with the browser's codecs (`createImageBitmap`, canvas `toBlob`), not pixel loops on the page.
- **E2E runs with service workers blocked by default**; only the `sw-*` Playwright projects allow them and run `tests/e2e/sw/` only. The app must work fully without the worker.
  - In WebKit, requests from a page controlled by a service worker bypass Playwright's `context.route`, so they would reach the real network. Specs in `tests/e2e/sw/` must not call OpenRouter. As a backstop, every project sends non-localhost traffic to a dead proxy.
  - Playwright's `setOffline()` in WebKit also fails requests the worker would answer from cache; offline specs use `startPrivatePreview()` (a private `vite preview` they shut down) instead.
  - Playwright's Firefox build does not start on some Windows 10 machines ("side-by-side configuration is incorrect", `mozglue`). There, run with `E2E_SKIP_BROWSERS=firefox`; CI runs Firefox and WebKit in its e2e matrix.
  - The mock enforces OpenRouter's real CORS allow-headers list on the actual request (Chromium and Firefox answer preflights inside Playwright) and serves binary bodies; `mock.file()` serves `tests/fixtures/media/`. `mock.respond(method, path, fn)` answers from the request body (pages sent in parallel arrive in any order); `sseResponse(chunks)` builds a stream for it.
  - The mock serves SSE bodies in one piece (`route.fulfill` cannot stream), so event parsing is tested but pacing is not.
  - WebKit behaves like Safari's defaults: Tab (and, in Playwright's Windows build, Alt+Tab) skips links, and a click does not focus a button. Keyboard specs Tab to buttons and fields (`tabTo()`), and focus-return checks open things from the keyboard. A background tab runs no transitions, so multi-tab specs `bringToFront()` the page they drive.
  - Playwright's WebKit on Windows crashes its renderer during cross-document view transitions (measured on the Stage 1 build too), so the `webkit` project emulates reduced motion on win32 only; CI (Linux) keeps transitions.
  - Specs in `tests/e2e/sw/` avoid tool pages: tool pages read the model catalog from openrouter.ai, and in WebKit a worker-controlled page's requests escape the mock.
- **Fixtures named `*.documented.json` were written from the docs, not recorded**, because development had no API key. Replace them with recordings when a key is available.
- **Core state services** (`src/core/{bus,settings,runs,budgets,stats,history,prompts,jobs,results,tool-state,backup,data}`). Each is `createXService(core)` and reads other services from `core` only at call time, so the composition root can fill one object in any order. `src/core/testing/state-fakes.ts` wires them the same way for tests.
  - **Budgets read the local ledger** (`stats` rows, written when a run finishes), never OpenRouter's lagging `/key` usage, plus the `reservedUsd` (or spend so far, if more) of every `running` run (all tabs). `begin()` checks and writes the reservation under the Web Lock `ortoolbox:budget`, so parallel runs see each other; a declined confirmation deletes the record. Runs on free models only with a 0/unknown estimate skip budgets. If spend cannot be read, the verdict is `confirm` (warn and hard). Stats survive "Delete all prompts and history"; only "Reset everything" clears them.
  - **Unknown cost is never free:** a run whose cost could not be determined (and every orphan the sweep finalizes that had sent a request) books `max(actual, reservedUsd)`. `run.checkpoint({ output: () => text })` takes a function, read only when the throttled write happens (and by `finish()` without an output). An orphan with `usage.requests === 0` sent nothing: it books nothing and its reservation is released.
  - **Run lifecycle:** a live handle holds the Web Lock `ortoolbox:run:<id>` (fallback: a `kv` `meta:run-heartbeat:<id>` every 30 s). pagehide only aborts; it does no IndexedDB work (the page may be gone). `runs.sweep()` (boot) finalizes `running` records with a free lock (or a heartbeat older than 3 min) and no open job. Runs continued by a job call `run.handOff(jobId)` and are finished by the job's completion handler via `runs.reattach()`. The final record and its stats rows are one transaction that refuses an already-final record, so spend is booked once; a failed final write can be retried. Storage failures never block a run. A data reset discards live runs (no writes afterwards) and stops job polling, in every tab. `history.restore()` (Undo) never brings a record back as `running` (it arrives `aborted`, its page is gone) and never books stats again.
  - **Jobs** poll under the Web Lock `ortoolbox:job:<id>` (`ifAvailable`); other tabs retry at the poll interval and take over when the holder closes. Poll results are written read-modify-write and dropped once the job is final, so a cancel from another tab wins. `attempts` counts failed polls; a non-retryable error or 20 failures in a row fail the job; `KeyLockedError` pauses until `keys-changed`. Removed jobs reach subscribers as tombstones (`removed: true`). A job books its end on the run before turning final (`usage` from `succeeded`; unknown cost, i.e. the reservation, on `gave-up`); `failureKind` separates provider failures (`remote`) from the core giving up. Notifications are opt-in (`notify`), and `run.cancel()` ends a handed-off run as `aborted`.
  - **Backups** wrap `core.keys.exportFile()` in a passphrase envelope (PBKDF2 iterations from files capped at 2 M). Every record is validated; invalid ones are skipped and counted in the preview. Merge: only settings present in the file override; runs/jobs are replaced only by newer copies and never move back from final; stats keep the max of each field; keys merge only under the same lock (a merge never removes a lock). Replace wipes keys only when the backup carries keys. Imported `running` runs arrive `aborted`; settings pointing at keys this browser lacks are dropped. Import writes keys (`replaceFile` with `expected`) and settings, then all IndexedDB changes in one transaction, rolling keys and settings back if that fails. Wrong passphrase: nothing is imported.
  - **Settings** `update()` re-reads storage before applying the mutator (no lost cross-tab updates); `pageshow` (bfcache) and becoming visible re-sync. Numbers are clamped to sane ranges and `__proto__`/`constructor`/`prototype` keys are never copied. `reset()` keeps `defaultKeyId` (keys are not affected). An older tab drops fields of a newer schema version on its next write.
