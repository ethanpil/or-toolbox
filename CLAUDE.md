# ORtoolbox — developer and agent guide

Browser-only toolbox of 14 AI tools on top of OpenRouter. No server, no accounts. The product spec is [PLAN.md](PLAN.md); the OpenRouter API facts we code against are in [docs/openrouter-api.md](docs/openrouter-api.md). Read both before changing behavior. This file records the architecture rules and the non-obvious decisions.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite dev server on :5273 under `/or-toolbox/` (no service worker; sends the isolation headers itself and a dev CSP built from the production table) |
| `npm run build` | Typecheck + production build to `dist/` (also emits `sw.js` and copies the ffmpeg cores) |
| `npm run preview` | Serve `dist/` on :4273 (service worker and CSP active) |
| `npm run check` | Typecheck + lint + unit tests — run before reporting any work done |
| `npm run typecheck` / `lint` / `format` | `tsc` on the three projects / ESLint + Prettier check / Prettier write |
| `npm run test` | Vitest unit tests |
| `npm run e2e:dev -- <spec>` | Playwright against the dev server (reuses a running one) — use this while developing |
| `npm run e2e` | Build, then the gate against `preview`: the default projects (service workers blocked) and the `sw-*` projects. It does not run the specs that import the page's own code, `tests/e2e/media` and `tests/e2e/dev` (dev server only: `npm run e2e:dev -- tests/e2e/media tests/e2e/dev`; CI runs both). Do not run it while other agents are working (it rewrites `dist/`). `E2E_SKIP_BROWSERS=firefox` leaves out a browser this machine cannot run; CI never sets it |
| `npm run budgets` | After a build: the shell's and each tool page's eagerly loaded JS against rule 8's budgets (CI runs it) |
| `npm run icons` | Regenerate `public/icons/*.png` and `favicon.ico` from `public/icons/logo.svg` (outputs are committed) |
| `node vite-plugins/third-party-notices.ts` | Regenerate `THIRD-PARTY-NOTICES.txt` (a unit test fails when it is stale; the build ships the same text as `licenses.txt`). An @ffmpeg/core upgrade also needs its release commit in `FFMPEG_CORE_SOURCE` there |
| `npm run icon-subset` | Regenerate `src/styles/_icons.scss` and the icon font subset after adding or removing an icon (outputs are committed; needs Python `fonttools` and `brotli`) |

## Layout

```
index.html, settings/, models/, history/, stats/, privacy/, diagnostics/,  platform pages (tiny HTML entry each:
auth/callback/                                                             <title>, <div id="app">, one module script)
tools/<id>/index.html                                                     one page per tool
src/core/        one folder per service (api, keys, oauth, models, settings, runs, budgets, history, prompts,
                 jobs, stats, results, tool-state, backup, data, bus), media/, export/, storage/, attachments/
                 (chat-request files: Chat, Model arena); contract in types.ts, errors in errors.ts, shared
                 helpers in util.ts, composition root in index.ts
src/ui/          dom.ts, markdown.ts, markdown-safe.ts (`safeBlock`: model text inside an exported Markdown document), format.ts, bootstrap.ts (the only Bootstrap JS imports), shell/ (mountPage,
                 navbar, palette, leave guard, appearance), feedback/ (toasts, dialogs, presentError), components/
                 (shared parts), tool/ (mountTool and the tool contract)
src/tools/<id>/  manifest.json + main.ts (+ tool-local modules and tests); registry.ts + types.ts beside them
src/pages/       code for the platform pages
src/styles/      main.scss (the shared stylesheet) + _bootstrap-subset.scss + generated _icons.scss/fonts/ + the few variable overrides in _variables.scss; tools/<tool id>.scss = one tool's own rules
src/sw/          the single service worker (sw.ts)
public/          theme-init.js, manifest.webmanifest, icons/, .nojekyll — copied to dist/ as-is
vite-plugins/    page discovery, shared <head> + CSP, ffmpeg core copying, service worker build, ports/base
scripts/         one-off generators (icons, icon-subset)
tests/e2e/       Playwright specs (sw/ = service-worker specs)   tests/mock/  mocked OpenRouter   tests/fixtures/  recorded/documented responses and media
tests/lint/      proof that the ESLint architecture rules fire
```

Adding a page = adding a folder with an `index.html`; the build, dev server and route tests all discover it (`vite-plugins/pages.ts`). The shared `<head>` (charset, CSP, viewport, theme color, manifest, icons, `theme-init.js`, the stylesheet) is injected by `vite-plugins/html-head.ts`; HTML entries must not repeat it. The same plugin adds the page's `<meta name="description">` (`vite-plugins/descriptions.ts`: a tool's manifest `description` plus a closing sentence, or an entry in its platform-page table; a page with neither fails the build and `tests/lint/html-head.test.ts`), the tool page's own `src/styles/tools/<id>.scss` if it exists, and a preload of the icon font.

TypeScript is three projects behind a solution-style `tsconfig.json`: `tsconfig.app.json` (src/, DOM), `tsconfig.sw.json` (src/sw/, WebWorker), `tsconfig.node.json` (configs, vite-plugins/, tests/e2e, tests/mock, tests/lint; imports use `.ts` extensions).

Tool ids (also the URL segment): `chat`, `ocr`, `data-extractor`, `table-extractor`, `speech-to-text`, `text-to-speech`, `music-generation`, `image-generation`, `image-editor`, `isolated-image`, `video-studio`, `decision`, `bot-to-bot`, `model-arena`.

Capabilities (keys for default models): `text`, `vision`, `image`, `tts`, `stt`, `video`, `music`, `decisions`.

## Architecture rules

1. **Pages never call OpenRouter or storage directly.** Tools and pages go through `src/core`. Only `src/core/api` may `fetch` openrouter.ai; only `src/core` may touch `localStorage`, `sessionStorage` or IndexedDB. This is what keeps keys, budgets, cost tracking and history consistent.
2. **Every model call belongs to a run.** A tool starts a run through the context (`ctx.runs`), which applies free-only mode and budgets before the request, captures usage/cost from every response, writes text-only history and feeds stats. Never call the API outside a run except for catalog/key/status reads.
3. **History is text only.** Images, audio, video and uploaded files stay in memory and are registered with the leave-page guard until downloaded. Never write binaries to IndexedDB or localStorage.
4. **Tool contract.** `src/tools/<id>/manifest.json` describes the tool; the shape is `ToolManifest` in `src/tools/types.ts` (`id`, `name`, `description`, `category`, `icon`, `capabilities`, `accepts`, `produces`, `usesJobs`, `lazyLibs`, `defaults`, optional `ownModels`; `usesJobs` and `produces` are descriptive only, nothing reads them; PLAN.md's example plus a one-line `description`, minus `entry`, which the folder convention makes redundant; `capabilities` use the list above). `src/tools/registry.ts` collects and validates the manifests. `main.ts` calls `mountTool(manifest, setup)` and receives one context object; [docs/tool-authoring.md](docs/tool-authoring.md) is the guide (contract, runs, results, jobs, prompts state, testing, a worked example). Tools use the shared components (drop zone, model picker, key chip, cost estimate, prompts panel, output panel, players, exporters) instead of rebuilding them. A tool folder may not import from another tool folder; shared code moves to `src/core` or `src/ui`.
5. **Three-zone tool layout:** input left, output right, settings in an offcanvas drawer; advanced options in an accordion. Stacks on narrow screens.
6. **Plain Bootstrap 5.3.** Stock components and Bootstrap Icons. Customization is limited to the Sass variables in `src/styles/_variables.scss`. No UI framework, no CSS-in-JS, no custom component library. Small utility CSS for things Bootstrap lacks is fine.
7. **No third-party origin at runtime.** Everything is bundled and self-hosted. The only network destinations are the static host and `https://openrouter.ai`.
8. **Heavy libraries are lazy.** pdf.js, ffmpeg.wasm, docx/xlsx writers, the chart library and the markdown renderer load with dynamic `import()` only when used. Budgets: shell ≤ 150 KB gzipped JS, each tool ≤ 80 KB more.

## Conventions

- TypeScript strict; ES modules; no `any` (ESLint `no-explicit-any` is an error: use `unknown` and narrow).
- Errors the user can act on are `OrError` subclasses from `src/core/errors.ts` (each has a `code`; the shell switches on `errorCode()`); never throw bare `Error`s for them. Small shared helpers (abort/sleep, type guards, prototype-safe JSON, UTC days) live in `src/core/util.ts`: import them instead of writing local copies. Web Locks go through `webLocks()`, `lockRunner(name)` (Web Lock plus the runner's own in-page queue: one per service or store, never module-level, or a test's late work runs inside the next test) and `holdLock(name, { ifAvailable })` there too. Token counts and the context fit have one home, `src/core/tokens.ts` (`approxTokens`, `MESSAGE_OVERHEAD`, `DEFAULT_OUTPUT_TOKENS`, `outputTokens`, `promptBudget`, `trimOldest`, `fitContext`). Data parsed from storage, files or the network goes through `parseJsonSafe`/`readJson` and is validated before use.
- Build DOM with the `h()` helper in `src/ui/dom.ts` (its header lists the rules: prop order, handlers, URL props limited to http(s)/mailto/tel/blob/relative, refused tags and props). Never put model output, file names or any other untrusted string into `innerHTML`. Markdown from models goes through `renderMarkdown()` (marked + DOMPurify), which also turns remote images into links so rendering never contacts another host, and keeps only an attribute allowlist (href, src, alt, title, align, colspan, rowspan, start, type/checked/disabled on task-list inputs, a `language-*` class on `code`): `class`, `data-*`, `role`/`aria-*`, `tabindex`, `hidden`, `for`, `popovertarget` and the like would let model output draw fake UI with Bootstrap, hide text that Copy code copies, or drive the page's real controls. With `USE_PROFILES`, DOMPurify ignores `ALLOWED_ATTR`, so the allowlist is enforced in an `uponSanitizeAttribute` hook.
- No inline scripts or inline event-handler attributes (CSP is `script-src 'self'`). No inline `style=""` attributes in HTML strings; set styles through CSSOM or classes.
- Internal links and asset URLs go through `url()` in `src/core/paths.ts`, because the site is served from `/or-toolbox/` on GitHub Pages.
- API keys are never logged, never placed in URLs, never written to history, and are masked in the UI (`sk-or-…a1b2`).
- Accessibility is part of done: labeled controls, keyboard reachable, visible focus, `aria-live` for streaming/status, contrast checked in light and dark.
- Motion is 150–250 ms, transform/opacity only, and off under `prefers-reduced-motion` or the Reduced motion setting. Color, border, shadow and size changes are instant (no `transition` on them); a fill that must grow smoothly uses `transform: scaleX`. Bootstrap's own stock transitions (collapse height, progress-bar width) are the one exception and stop under the same two switches.
- Unit tests live next to the code as `*.test.ts` (Vitest, jsdom; tests needing IndexedDB `import 'fake-indexeddb/auto'`). E2E specs live in `tests/e2e/`, import `test`/`expect` from `tests/mock/index.ts` (never from `@playwright/test` directly) and only talk to the mocked OpenRouter; no test may reach the real API. Use `watchForProblems()` from `tests/e2e/support.ts` to assert a page has no console errors, failed requests or CSP violations (it ignores `net::ERR_ABORTED` on `<audio>`/`<video>` reads of `blob:` URLs; aborts the app causes, a Stop or a stream canceled after `[DONE]` in production builds, are opt-in: `watchForProblems(page, { allowAborted: ['/api/v1/chat/completions'] })`), and `seedApp(context, { settings, key })` from `tests/e2e/app.ts` to start with onboarding done (and a test key).
- ESLint enforces two of these rules (proved by `tests/lint/`): no HTML-string sinks (`innerHTML`/`outerHTML` in any spelling, `insertAdjacentHTML`, `setHTMLUnsafe`, `parseHTMLUnsafe`, `createContextualFragment`, `document.write`), and no `localStorage`/`sessionStorage`/`indexedDB` outside `src/core` (also via `window.`/`self.`/`top.`/`parent.`).
- UI text uses US spelling (color, gray, center, canceled, summarize, organization), in strings, `<title>`s and manifests. Comments, identifiers, storage keys, test ids and instructions sent to models are not UI and may differ. `tests/lint/us-spelling.test.ts` reads the string and template-literal text of `src/`, the HTML titles and the manifests and fails on a British spelling; a literal that is not UI text goes on its `ALLOWED` list (`tests/lint/us-spelling.ts`) with the reason.
- Dependencies: assume your knowledge of every library is outdated. Check the installed version's docs or types before using an API. Do not add a dependency if one already in `package.json` does the job.
- Changelog: `CHANGELOG.md` in Keep a Changelog format, short entries, with the commit hash when known.

## Shell and UI

[docs/tool-authoring.md](docs/tool-authoring.md) has the how-to and code samples; the rules and reasons are here.

- **Every page** is `mountPage(options, render)` (`src/ui/shell/index.ts`): boot, appearance, navbar, `<main id="main">`, footer, one `<h1 data-testid="page-title">` (`header: false` to render your own), palette (Ctrl/Cmd+K), leave guard, budget confirmation (`runs.setConfirmHandler`), auto-lock activity. Script navigation goes through `page.navigate()` so the leave guard sees it. **Tool pages** are `mountTool(manifest, setup)` (`src/ui/tool/`), which calls `mountPage`.
- **Deep links** (`src/ui/shell/links.ts`): Settings gives every `SETTINGS_SECTIONS` id (`keys`, `models`, `tools`, `budgets`, `appearance`, `security`, `data`, `backup`) an element and opens it from the URL hash; the palette, errors and onboarding link there. History reads `?tool=`/`?run=`; Models `?q=`; tools `?run=`, `?prompt=`, `?model=`, `?sample=1`, `?receive=`.

### Feedback

- **Errors:** `presentError(error, { retry })` switches on `errorCode()`; throw `OrError`s and let it decide. It ignores an error already shown (`markPresented`/`wasPresented`). `userMessage` keeps an `ApiError`'s own message (the client's 402/429 wording) and goes generic only when it is empty. `storage-unavailable` (browser blocks Web Storage) is a toast that stays until closed ("This browser blocks saving"), no Retry; `mountPage` says it once per load (`noticeIfStorageBlocked`, probing with `webStorageBlocked()`). The `free-only` toast words its advice for what was refused (`FreeOnlyError.models`, `.addons`): a paid model says "Pick a free model", a paid add-on (a PDF parser) names it and says to switch it to a free option in the tool's settings, both say both.
- **Toasts** announce through two persistent live regions (`announce()`), never by being live regions; `announce()` says the same line once when repeated within 1 s (panel, status line and tool often report one event). A toast with an action never hides by itself (WCAG 2.2.1) and its actions run once. Alt+Shift+N (`TOAST_SHORTCUT`) focuses the newest toast (the container is last in the page); focus returns on close. On narrow screens the container sits above the Run bar (`--or-runner-height`).
- **Modals:** `openModal()` is the only builder: one at a time, later calls queue (`modalOpen()` tells shortcuts to stay out); `hide()` during the show transition is deferred (Bootstrap would drop it). Parallel no-key errors share one add-key dialog. Offcanvases opened from code use `showOffcanvas()` so focus returns to the opener; Bootstrap keeps one focus trap, so a modal closing over an open offcanvas re-arms it (`restoreOffcanvasTrap()`). Field validation: `setFieldError(input, feedback, message)`.
- **Costs** are worded only by `describeRunCost`/`formatRunCost`/`usageLine` (`format.ts`): unknown first (never free or `≈`; says what budgets counted), then free, estimated (`≈`), known. An inline error uses `failureText(error, { blind })` (`feedback/errors.ts`), never bare `userMessage`: it keeps the "may have been billed" caution and the activity link. `blind: true` (the arena before names show) makes every failure read alike (generic text, `BLIND_ACTIVITY_NOTE`, activity link, `outcomeUnknown` false), because a 402's credits, the 429 free-model text, provider names or a missing Retry would give a paid model away.

### Runs in a tool (standard patterns; tool sections only list deviations)

- **One error rule:** a tool catches, calls `output.fail(error)`/`run.fail(error)`, and rethrows; the runner decides what shows. Stop (`aborted`/`cancelled`) is silent apart from a neutral "Stopped" (partial output stays). Errors that need an action (no key, locked, free-only, budget, storage) always go to `presentError`. Any other error is shown once: inline by `outputPanel.fail(error)` (marks it presented, words it with `failureText`) or else by the runner's `presentError`. Outside a runner, call `presentError` yourself.
- **Maybe billed:** a paid request that may have gone through (`isOutcomeUnknown`) is never resent by a plain Retry. The runner's toast offers the tool's `safeAction` or the activity link (`retryUnknownOutcome` only when a resend cannot pay twice); `runItems` never marks such an error presented; per-item Retry is `retryGate(runner).retryFailed(error, keys)`, which confirms first ("This may have been billed"). Draw inline failures with `failureLine(failure)`; keep the flag with a stored message.
- **Refused runs change nothing:** read the form into a plan, call `ctx.beginRun` (may refuse: no key, locked, free-only, budget, Cancel), and only then reset results, mark items or start the panel. **Snapshot per press:** the plan, estimate, add-ons, free-only check and every request come from the form as it was when Run was pressed (taken before `beginRun` and its dialogs), never re-read later; a file dropped meanwhile belongs to the next run.
- **Runner arguments:** `trigger(arg)` passes `arg` to `run(signal, arg)`; the error toast's Retry replays it. `trigger()` returns `Promise<void> & { started }`; `subscribe` reports `{ busy, disabledReason }`. `replayArg: pendingOnly(isDone, allKeys)` narrows the replay to items without a result (a plain run too when `allKeys` is given), so a 402 mid-retry never pays twice; a replay that cannot start says why in a toast. Per-item Retry goes through `retryGate(runner)` (`bind`, `retry`, `retryFailed`, `blocked`; a vanished focused Retry sends focus to `fallback()`, default Run).
- **A bar with more than Run** is built on the runner (`setLabel`, `hideWhileBusy`, `addAction`; a `run` action is off exactly when Run is). The runner moves focus to the first visible bar control when the focused one hides; Ctrl/Cmd+Enter stays Run with no argument. Never rebuild the bar by hand.
- **Escape stops:** `stopOnEscape` (`stop-on-escape.ts`) is installed by the primary runner (`RunnerOptions.stopOnEscape`: `{ allowIn }`, or `false`) on `plainShortcutAllowed`, so Ctrl/Cmd/Alt+Escape, dialogs, fields (unless in `allowIn`), selects, an open drawer or menu and input-method composition (`composing(event)`) are left alone.
- **Batches** go through `runItems()` (`batch.ts`, over `runPool`; `concurrency` is required, neither has a default): statuses `queued → running → done | failed | stopped`; a failed item does not stop the rest; a fatal error (`isFatalError`) stops scheduling and is rethrown unmarked (it needs presenting); Stop rethrows the abort reason; an all-failed batch rethrows its last error marked as shown (the items show it) unless an item's outcome is unknown (then unmarked, so the caution toast shows). Each failed outcome carries `failure` (`failureText`), drawn by `failureLine()`.
- **Groups of runs** ask one budget question for the total: `runs.beginAll(specs, { label })` (start together, all or none) or `runs.approveGroup` + `beginRun({ groupId, useGroupApproval })` (over time: video sequence); unknown members are counted ("≈ $0.27 + 1 unknown"). Otherwise every run asks for itself.
- **Paid add-ons** (`RunSpec.addons`, `src/core/runs/addons.ts`): each has its own estimate; `runs.begin` adds the known parts to the models' estimate (null only when nothing is known) for budgets and the reservation, refuses a paid one (estimate not 0, unknown included) in free-only mode, and a run with one is never "free" for budgets. Tools declare them with `ToolInstance.addons()`, outside `estimate`; the badge shows model + add-ons. PDF engines and the Mistral OCR price ($2.20 per 1,000 pages: the announced $2 plus the 10% US regional rate; the docs page does not render the number) are in `src/core/models/pdf-engines.ts`.
- **Unsaved work:** the leave guard covers results (`ui.addResult`) until downloaded and in-memory work held with `ui.holdWork()` (`results.hold()`); it also arms the browser's prompt, and adds its own `beforeunload` while a run of the page (not handed off) is going. It ignores handed-off runs (`RunHandle.jobId`): the job carries on without the page. `ui.confirmDiscard({ what, isDirty })` (`discard.ts`) is the one "replace unsaved work?" question, asked before `beginRun`.
- **Result cards** (`imageResultCard`, `audioResultCard`, `videoResultCard`) remove through `resultRemoval()` (`components/result-removal.ts`): `beforeRemove` defaults to `confirmUndownloaded` (a paid result not downloaded asks first; compose your own check with it); the focus fallback runs after `onRemove`. SVG results are offered as PNG and as an SVG cleaned by `sanitizeSvg` (DOMPurify SVG profile, which also drops `<use>`; no `foreignObject`, no external `href`, no CSS that loads files); the registered blob becomes the clean one, so Download all saves it.
- **Streaming** text is drawn by `streamMarkdown()` (`components/stream-markdown.ts`); `outputPanel` wraps it. `exportMenu()` returns its element with `update()`, so it is built once (rebuilding closed an open menu).
- **`"ownModels": true`** in the manifest (Model arena, Bot-to-bot) drops the header's model chip and free-only substitution note (Run is still disabled with the notice when free-only leaves no model), and Settings → Tools shows "Chosen inside the tool". The binding is only the starting model of a new setup, so no UI writes it; an old one is shown and Reset clears it.
- **File types:** the drop/paste guard, drop zones and Send to… match `accepts` on every type a file can count as (`fileMimes`: the browser's and the extension's); which extensions are text is Chat's `classifyFile` (`core/attachments`), so `.tsx`/`.vue`/`.kt` reach Chat and a `.ts` Windows calls `video/mp2t` is text and video alike.
- **Send to…** hands items over in memory: the source opens `tools/<id>/?receive=<id>` and answers the target's `ready` on BroadcastChannel `ortoolbox:send`; nothing is stored. jsdom cannot structured-clone its own Blobs, so the unit test checks the handshake, not Blob bytes.

### Framework internals (`src/ui/tool/`)

- The drop/paste guard (`file-drop.ts`) is installed before `setup`, so a stray drop never navigates away. Estimates come from `ToolInstance.estimate(model)` through `estimate.ts` (a version counter drops answers older than the newest request); `ctx.beginRun` always computes the estimate afresh (a debounced refresh may lag the input), and only `ui.setEstimate` values are reused. `createToolContext` (`context.ts`) serves the page and `createToolTestContext` (`testing.ts`). The main prompt field is `data-testid="tool-prompt"` (unless the instance is `promptless`).
- **Sticky Run bar keeps focus visible:** `--or-runner-height` feeds `scroll-padding-bottom` (`scroll-padding-top` clears the navbar). Chromium ignores scroll padding for Tab, so a focused control a bar still covers (`uncoverBy`, `uncover.ts`: the bar must overlap it horizontally too, since on wide screens it sits in the left column; controls in a modal or offcanvas are skipped, and so is focus that is not `:focus-visible`: a press on blank space focuses `<main tabindex=-1>`, and scrolling then cancelled a native drag begun on a handle, the Decision score scale's; `shell.spec.ts` presses blank space and expects no scroll) is scrolled clear on the next frame and again when the focus scroll ends (`scrollend`, else a 700 ms timer), because Bootstrap's smooth scrolling may still be moving it.
- Until `setup` resolves, the zones row is `.or-tool-pending` (`visibility: hidden`, 60vh floor) and the chips row has one chip's height, so nothing shifts when the tool fills in.
- The test harness `cleanup()` is async: stops runners, `settle()`s (idle runners, no tool-state call in flight for two 25 ms checks), then drops bus listeners and Escape handlers.
- The status line is not a live region: `ui.status` announces through `announce()`, `ui.progress` at most every 10 s (`status-line.ts`).

### Shared helpers and components (use them; no local copies)

- `format.ts`: `formatInt`, `formatDate` (a timestamp, or a `YYYY-MM-DD` UTC day), `keyBalance`, `shorten(text, max)`, `stemFrom(text, fallback)`, `fileStamp(time)` (local-time stamp for file names), `isoDateTime()` (stored time into `<time dateTime>`; undefined where `toISOString()` would throw). No page calls `toLocaleString`/`toLocaleDateString`.
- `core/util.ts`: `DAY_MS`/`HOUR_MS`/`MINUTE_MS`, `debounce(fn, ms)` (cancelable; `SEARCH_DEBOUNCE_MS` for search boxes), `createTicker()` (the "Generating… 12 s" line). `clipboard.ts`: `copyWithToast`. `settings-actions.ts`: `saveSettings` (shows a failed save; `onError` replaces that), `setToolBinding`, `toggleFavoriteModel`/`toggleFavoriteTool`, `setTheme` (`THEME_MODES` is in `shell/appearance.ts`). `core/models/capabilities.ts`: the one `CAPABILITY_INFO` (`label`, `title`, `badge`, `filter`, `icon`). `findTool(id)` (`tools/registry.ts`) looks up ids from storage (`getTool` throws).
- Components (`src/ui/components/`): `starButton`/`setStarred`, `dataTable` (scroll region with `position-relative`, named and focusable, `th scope`, numeric columns from `numericFrom`; pass your own `body` when the page re-renders rows), `keyBalanceView` (one state machine and wording for Settings, Stats and the key menu), `loadInto` (skeleton, status, error state with Try again; a newer call on a container supersedes an older one; `keepOnLiveFailure` for live reloads), `externalLink`, `switchField`, `meter`, `progressBar`, `createMarkdownCache` (finished messages rendered once; optional `decorate`: Chat's code Copy buttons), `attachmentIntake({ noun, … })` (dropped, pasted and Send-to files with one set of limits and wording: Chat's composer, the arena's prompt). Small icon-only buttons are `btn btn-sm btn-link or-icon-action` (`.or-icon-button` is the Models page's compact copy button).
- Searching a catalog goes through `rankBy` (`shell/palette-search.ts`): the query is normalized once per search and each object's fields once, cached per `describe` function.
- Shortcuts follow `shell/shortcuts.ts`: a plain key (Home's `/`) is ignored in fields, selects and dialogs; Ctrl/Cmd+K works in fields but never opens over another dialog (then the browser keeps the key). The palette opens without Bootstrap's fade (`animate: false`): a fading modal is unfocusable until its backdrop finishes, and keystrokes typed right after Ctrl+K would land on the page.
- **Re-rendering keeps focus** through `replace(container, ...children)` (`src/ui/dom.ts`): the focused control's `data-focus-key` is looked up in the new children (gone or disabled: the nearest keyed control that can take focus, following ones first, then the first focusable element), and Bootstrap instances inside the old ones are disposed. `focusedKey(root)`/`focusKey(root, key)` do the same for a single swapped node; `replaceWith(el, children, { fallback })` lets a page pick the landing place (Settings: section headings). Product code never reads `data-testid`.
- **`.visually-hidden` in a scroller** is absolutely positioned, so in an unpositioned `.table-responsive` it escapes the overflow and widens the page on phones: give the scroller `position-relative`.

### Look and platform

- **Bootstrap JS** is imported per plugin from `bootstrap/js/src/*.js` (typed in `src/ui/bootstrap-js.d.ts`); `data-bs-toggle` works because each import registers its data API. Never the bundle.
- **Look:** canvas `--or-canvas` behind `--or-surface` cards (light: gray behind white; dark: body behind tertiary), `--or-inset` for recessed areas. Bootstrap's outline buttons are recolored in `_shell.scss` because their stock text colors miss AA on the canvas (secondary) and in dark mode (primary, danger, success). A global `[hidden] { display: none !important }` beats display utilities. Custom CSS is one partial per concern in `src/styles/`.
- **Accent color** is applied at run time: `shell/accent.ts` derives Bootstrap's shades plus link and outline text at 4.5:1 on every surface of the theme (light: white cards and the `--bs-tertiary-bg` canvas; dark: body and card), focus outlines and the focused-field border at 3:1 (`--or-focus-color`/`--or-focus-border`), and check/radio/switch glyphs in `--or-accent-contrast` (SVG data URIs as custom properties). `accent.test.ts` checks a color sample; `appearance.ts` sets them on `<html>` with `data-accent`; `_accent.scss` re-points components Bootstrap compiled with fixed colors. Theme and accent changes switch with transitions paused for two frames (`data-no-transition`).
- **theme-init.js** also sets `data-density` and `data-reduced-motion` before first paint, handles the incoming view transition (`pagereveal` fires before any module runs) and silences only Chromium's "Transition was aborted/skipped" rejections (a promise no script can reach; navigation is unaffected).
- **Onboarding** is an inline wizard on Home (a modal would block Home for every first visit and e2e test); its step is `settings.ui['home.onboardingStep']`, so the OAuth round trip comes back to it.
- **Settings** (`src/pages/settings.ts`, sections in `src/pages/settings/`): one panel per `SETTINGS_SECTIONS` id, chosen by the hash; `hashchange` focuses the section's `<h2>` (that is the announcement); a non-section hash such as the skip link's `#main` is ignored. A section is built when first shown (a visit to `#keys` never loads the model catalog), loads its numbers then (`onShow`) and re-renders from service subscriptions through `rerender()` (focus back by `data-focus-key`, else its `fallback`). Undo of a key removal re-inserts the key (same id, so its stats and budget follow) into the keys file as it is at Undo time (`keys.replaceFile(next, { expected: current })`) and restores its default/tool pins/per-key budget only where nothing replaced them; the entry is held in memory until the toast closes. `freeOnlyModel()` in `logic.ts` mirrors `ModelsService.resolve` with free-only on, to preview it while off; a unit test keeps the two in step. Budgets meters and "Spent this month" read `budgets.monthSpend()` (the numbers `check` uses, including running runs' holds; one read for total and every key); a figure with an estimate reads "≈" like Stats, and the page refreshes on stats and history changes, so a meter never shows room `check` would refuse. Deletions say what they kept (`deletionKeptNote`).
- **Dev-only e2e:** `tests/e2e/dev/` (like `media/`) imports the page's own core from `/src`, so it runs only against the dev server (`npm run e2e:dev -- tests/e2e/dev`) and no test hook ships. It covers shell states a tool page cannot easily produce (results not downloaded, runs in progress, budget confirmation).
- **Interop and flows with no tool around them:** CI opens a workbook written by `src/core/export/xlsx.ts` (the sample in `xlsx-sample.ts`, written by `xlsx-sample.test.ts` when `XLSX_OUT` is set) with openpyxl, a reader that shares none of our code (`scripts/check-xlsx.py`; change the sample and the checker together). `tests/e2e/oauth.spec.ts` runs "Connect with OpenRouter" against the mock: `/auth` answers with the redirect to the callback (the mock's `respond` reads `callback_url` and `state` from the query), `POST /auth/keys` with a key; it checks the PKCE challenge against the verifier. A spec that holds a stream open to Stop it (Chat, Image generation) does so with an in-page `fetch` wrapper; a request shows its images or reply only when it ends, so such a spec waits on the reader asking for more (`pull`), not on the screen.

## Platform pages: Models, History, Stats

Each is a class in `src/pages/<page>.ts` over a pure, unit-tested module (`models-logic`, `history-logic`, `stats-logic`) that holds every rule about filtering, paging, grouping and aggregation; the page only draws. E2E specs seed IndexedDB through `tests/e2e/seed.ts` (`seedDb`: runs and stats rows, then a bus message so open pages update live).

- **Models:** the catalog (~650) is filtered in memory and drawn 48 at a time ("Show more", and automatically through `whenVisible()` in `src/pages/lazy.ts`); no virtual list. Free means `:free` id only (zero prices are not a signal). **Prices come from one model, `src/ui/model-price.ts`** (`modelPrice`, `describePrice`, `comparablePrice`; `formatModelPrice` delegates to it), so picker, tool chip, Settings and this page agree: the unit is the model's real billing unit (1M tokens, image, 1M characters or bytes, hour of audio, second of speech, clip, request, or "varies" for video and routers), chosen with the same heuristics as `src/core/models/estimate.ts`; token-priced chat models with audio or image output get an extra line. Price sort puts free first, then each unit on its own (never an image price against a token price). "Max price" compares input plus output per 1M tokens in micro-dollars; free always passes, models billed in another unit never do, and the page says how many that hides (`hiddenByPriceLimit`). Your own stats per card come from one ledger read (`usageByModel`, rebuilt on `stats.subscribe`), never one query per card. "Retry" after a failed load asks the network (`refresh: true`): the cache remembers a failure for five minutes. Card/table choice is `settings.ui['models.view']`; `?q=` is kept with `replaceState`.
- **History:** pages by cursor `before = last.startedAt + 1` and drops rows already shown, because parallel runs (arena) can share one millisecond and an exclusive cursor would skip them. `HistoryService.restore(runs)` is Undo for delete (like `prompts.restore`; never touches stats, never brings a run back as `running`). Runs in progress are never deleted (not by "Delete filtered" either, which says how many it kept). Delete asks first and offers Undo; "Delete filtered" needs the typed word and offers Undo too. The model filter is built from the runs themselves (`model` and `models`, so ids behind `openrouter/free` are there), read once in pages in the background; after that a change that names its runs (`history.subscribe` passes ids) reads only those, and the whole history is rescanned only when a run went away or a change named none. Text search tests each field with one case-insensitive regex, short fields first, and never lowercases a copy of an output. JSON output is re-indented by `prettyJson`, which copies number literals, strings and duplicate keys as written (parse and stringify would turn `12345678901234567890` and `1e999` into other numbers). The run drawer is an offcanvas: Bootstrap handles Escape only while focus is inside it, so `keepDrawerFocus()` restores focus after every rebuild; a live update arriving while it slides in must not be dropped (`currentRun` is the gate, not the `show` class). Runs seeded as `running` are finalized by the page-start sweep, so specs write them after load. `?tool=`/`?run=` are kept in the address bar. **Records this build cannot draw:** a stored time goes through `isoDateTime()` and a stored tool id through `findTool()`: History still lists a run of an unknown tool (named by id, no Reopen or Re-run; exportable, deletable); Home and the palette leave it out; a job's notification says "Job".
- **Stats:** works on the daily ledger (`stats.rows`), so its days are **UTC** and it survives pruned history. The ledger is read once per load; range, previous range, this month, today and each key are derived in memory (`rowsIn`), so changing the range reads nothing. Relative ranges (7/30/90 days, this month) are resolved again on every load (`resolveRange`); a timer at the next UTC midnight (plus `visibilitychange`) reloads, so an open page rolls over; a custom range stays as chosen. **Ledger semantics (core):** `StatsRow.runs` and `errors` count on the primary model only, so a multi-model run is one run and one error (the others gain requests, tokens and cost) and `errors / runs` is a real error rate; `StatsRow.estimatedUsd` is the part of `costUsd` that is an estimate (the whole cost when `usage.costEstimated`, plus a booked reservation), shown as `≈` in the KPI (with "Includes $x estimated"), tables, chart tooltips and table views. Charts are Chart.js (spend, requests, tokens), imported dynamically from `stats-charts.ts` only when there is data, with just BarController/BarElement/CategoryScale/LinearScale/Tooltip registered. Colors are `--or-viz-1..7` and `--or-viz-other` in `_pages.scss` (validated for color-blind separation against both themes' card surfaces; three light hues are below 3:1, so every chart has a legend, tooltips and a table view as relief); charts read the tokens at run time and restyle on a `data-bs-theme` or `data-reduced-motion` change (MutationObserver). Series colors follow the entity, not its rank: `assignSlots()` keeps a slot from the all-time rank, so a range change does not repaint survivors; beyond seven series the rest is "Other" (gray), never an eighth hue. Every chart has a text alternative (the canvas's label), a legend that toggles series (none for one series, and then nothing may stay hidden: `pruneHidden`) and a table twin. The tooltip title comes from the active element, not the filtered items, or an empty day would show the first day's date. Budget, free-today and key balances are always the current month/day, not the chosen range. Page classes Settings could also use are prefixed (`.or-legend-swatch`, `.or-stats-meter`); small targets meet 24 × 24 px.

## Document tools: OCR, Data extractor, Table extractor

- **One input component**, `documentInput()` (`src/ui/components/document-input.ts`, range logic in `page-selection.ts`). Nothing is rendered up front: tools call `loadPage(ref)` inside their own run, so a 200-page PDF never sits in memory as images. At most two PDFs stay open (LRU idle one closed, reopened on demand); thumbnails are small JPEGs, two at a time, only for tiles in view. pdf.js and the image module are imported once per page via a cached promise (Vitest never settles concurrent dynamic imports of one mocked module).
- **Runs:** one run per press (per batch for the Data extractor), items through `runItems` with the user setting "at the same time" (1-3, default 3). Output is text only (OCR's combined Markdown, the extractor's JSON, tables as Markdown), checkpointed as items finish. Batches, fatal errors and Retry are the standard pattern (Shell and UI); retrying failed items is a new run that books its own estimate.
- **A press is read once** (`Began` in each tool; OCR's is `began.s`): every setting and the instructions are read when Read/Extract/Find tables is pressed, and the estimate, add-ons, free-only check and every request come from that snapshot, never the form. `documentInput`'s `maxSide` callback reads it during a run, so changing image size, parser or text hint mid-run cannot change a page's cost (OCR switching to Mistral mid-run once billed unreserved pages). The estimate goes to `beginRun` explicitly; History keeps the snapshot.
- **Replay and Retry:** `replayArg` is `pendingOnly(isDone, () => pressed ?? [])` over the keys of the press that began (`pressed` is null until `beginRun` accepted a press, so a refused press replays whole). A failed item shows `failureLine`, keeps its error in a map and retries through `retryGate(runner).retryFailed(error, keys)`.
- **Edited results are unsaved work:** the Data extractor's corrected cells and the Table extractor's edited tables are held (`ui.holdWork`) until the export menu builds a format. Extract / Find tables asks first (`ui.confirmDiscard`, before `beginRun`) only if something was edited since the last export; a retry replaces only retried items and never asks. History keeps what the model returned, not corrections (no `history.update`).
- **Refusals:** OCR checks the streamed reply's `refusal`; the extractors check a non-streamed answer's `message.refusal` or `content_filter`/`error` finish with no content (`responseRefusal` in `extract.ts` and `tables.ts`, one copy each: tool folders cannot import each other). The item fails with the refusal's words; the Data extractor skips its repair request (it would only pay for the same refusal).
- **Model limits:** output is `min(tool cap, outputCap(model's cap))`; `temperature` and `max_tokens` are sent only when the model lists them. The extractors fall back from strict to JSON mode (`fallbackMode`) for the rest of the batch when no provider serves the strict request, and say so in the status line. **Estimates** count a page image at `imageTokens(maxSide)` (pixels / 750 for an A4 page; each tool holds the formula) plus the PDF text hint when on.
- **Structured outputs by catalog flag:** `structured_outputs` in `supported_parameters` → `response_format: json_schema` (strict) plus `provider.require_parameters: true`; only `response_format` → JSON mode with the schema in the prompt; otherwise the prompt alone. The Data extractor asks once more (bad answer + problem) when an answer is not a usable JSON object. Strict schemas list every property as required; optional fields are nullable. The mode rules (`outputMode`, `fallbackMode`, `isUnsupportedStrict`) and the refusal check on a non-streamed answer (`responseRefusal`) are shared by the Data extractor and the Table extractor in `core/api/structured-output.ts`; `imageTokens` (page-image estimate) is in `core/models/estimate.ts`.
- **Data extractor:** saved field sets change through `ctx.state.update` and follow `tool-state-changed`, so two tabs never overwrite each other; a set in use that is deleted elsewhere stays in the form as Custom, as does History's `saved:<id>` for a deleted set (the set in use is remembered in `options.schema`). Field and column names `__proto__`, `constructor`, `prototype` are refused (the response parser drops those keys, so an answer filed under one never arrives), as in Decision. Values are normalized on arrival and on every grid edit (`schema.ts`: `1.234,56`, `(12.00)`, ISO dates, choices); doubtful values stay as typed and are flagged, never dropped. Exports read the grid's current values. XLSX: currency `#,##0.00`, dates as serials, one sheet per table field keyed by document number. `readNumber` strips only real ISO 4217 codes in capitals and currency symbols, never any three letters ("5 and 6" once read as 56).
- **Table extractor naming:** an untitled table keeps `title: ''` and shows as "Table N" by position (`tableTitle`), so the order pages answered in never names a table. A read that found nothing says "No tables found". Undo of a deleted table is refused only after a read that replaced the tables (`extraction` is bumped by plain runs, not by a retry of failed pages). A retry cannot touch a merged table: failed pages have none.
- **OCR's PDF parser:** `cloudflare-ai` is the free default; `mistral-ocr` is billed per page even with a free model, so free-only mode refuses the run before anything is sent (`FreeOnlyError` with only `addons`). OCR presents that refusal itself (a "Free-only mode is on" toast, "Choose the free parser in Settings", a button opening the drawer), because the framework's notice would say "Pick a free model". The plain-text export honors Page separators like the Markdown.

## Chat (`src/tools/chat/`)

- **Threads are trees** (`thread.ts`): a node's `parent` is the source of truth, `children` only keeps order, `selected` the branch shown. Edit and regenerate add siblings; the active path is what is shown, sent and exported. One tool-state key per thread (`thread:<id>`, plus `current`). `parseThread` repairs whatever storage returns (orphans, cycles, bad selections, `__proto__` ids), turns a reply left `streaming` into `stopped`, refuses newer versions (left untouched) and reads the linear JSON export. Undo of "Delete from here" re-inserts the branch into the thread as it is now (`restoreBranch`), never a snapshot; during a reply it waits for the run to end.
- **Tabs and writes:** each write is one `ctx.state.update` (read, three-way merge, `rev` bump, write under the key's Web Lock), so two tabs never write the same `rev`. Every write is announced as `tool-state-changed` and Chat re-reads that thread (its own writes compare equal and stop). A tab merges a newer stored version (`mergeInto`, three-way against `baseOf` what it last read or wrote) when told or when it finds one while writing, never writing over it: additions on both sides kept, deletions on both stay deleted, a reply keeps its most final version, one streaming here is untouched. Navigation (‹ ›, opening a thread, picking the same model) writes nothing; `current` is written only when this tab opens, starts or deletes a thread. A thread deleted elsewhere while this tab replies in it is written back.
- **Attachments:** shared with Model arena in `src/core/attachments/` (`missingInput`, `parserAddons`, `keepParsed`, limits; `approxTokens` re-exported from `core/tokens`); chip is `attachmentChip()`. Only text files keep their text (1 MB each, 2 MB per message, Send to too); image, PDF and audio bytes live in the session map while a message (any branch or thread, or the composer) refers to them, and an Undo keeps them for its toast. After a reload, or for a model without that input in earlier messages, they go as a one-line note (`missingNote`, kept in Chat because the shared `toContentPart` returns null without bytes) and the message says "Attachment not kept after reload". The message being answered is refused instead when the model lacks the input (image, audio, or file for the `native` PDF engine).
- **PDFs are read once:** the turn that sends a PDF streams like any other; the parser's text returns in `ChatStreamResult.annotations`, is stored on the attachment (`parsed`) and later turns send it as text (no upload, parsing or plugin; survives a reload). The engine comes from `src/core/models/pdf-engines.ts`; a paid one is a run add-on (`addons()` for the composer, `beginRun({ addons })` for what a request parses; pages counted from `/Type /Page` objects or guessed high from size).
- **Limits:** `approxTokens` (`src/core/tokens.ts`) is deliberately high (rules in its header: digits and ASCII marks count extra so JSON and code are not under-counted; CJK, Hangul, kana, Indic, Thai 1 per character). `max_tokens` is clamped to the model's output cap and the context left after the prompt (`promptBudget`, `trimOldest` keeping a user message first, `fitContext`); a message that alone does not fit is refused before the run. The estimate is the dearest of the model and its fallbacks.
- **Rendering:** the conversation is `role="region"`, not a live region; `ui.status` announces Reply started/complete/Stopped. Messages redraw only when `messageSignature` changes; an arriving reply streams through `streamMarkdown`. Runner state never rebuilds them: `runner.subscribe` feeds `applyRunState`, which sets `aria-disabled` (focus stays) on buttons that start a run or change the thread while busy. Focus keys name the place (`regen:<parent>`), so focus survives ‹ ›, Regenerate and Retry. The Export menu is built once and updated in place.
- **Runs:** every send, edit or regenerate is one run booking an estimate for exactly what is sent (`estimateUsd`; a chat's model may differ from the header's). Messages are committed only after `beginRun` resolves, so a refused run leaves the composer as it was; if the thread changed meanwhile (another tab deleted what the reply answers) and the messages cannot be added, the run ends failed instead of staying `running`. The action is the runner's argument (`ui.runner<Action>`), so the toast's Retry repeats it, except that an error after the reply started that needs a dialog retries as a Regenerate of that reply (a replayed send would add a second message). Other errors show inline through `failureText`; one that may have been billed stores `outcomeUnknown` on the node, shows the caution and activity link and offers no Retry (Regenerate stays). The run's `settings` hold the concrete model; `applyState` ignores the model on a `?model=` visit. Escape stops a reply (`stopOnEscape: { allowIn: [composer] }`). A request with `input_audio` is estimated with `audio: { input: true }`.
- **A streaming reply is billed work:** every text event calls `run.checkpoint({ output: () => reply.content })` and schedules a thread save at most every `PROGRESS_MS` (1.5 s), so a reload or crash keeps the partial text and a swept run has output in History; no hold is needed (the leave guard counts a live run). A `ChatStreamResult.refusal` (declined, or a filter blocked it with no content) becomes a failed reply (`status: 'error'`, content cleared so it is never sent back as the model's earlier answer) with Retry; the run is finished (billed) with the refusal as output.
- **E2E:** the mock cannot stream, so the Stop spec holds the stream open with an in-page `fetch` wrapper. Unit tests `settle()` (runner idle, `kv` unchanged) before the next test resets the database, or a late thread write lands in it.

## Speech-to-text (`src/tools/speech-to-text/`)

- **Input** (`source.ts`): audio in a format the API reads (mp3, wav, flac, m4a, ogg, webm, aac), at most one part long and 15 MB, is sent as is. Everything else (long audio, video, other formats, any file for a WAV-only model) is decoded to 16 kHz mono (`decodeAudio`; ffmpeg's `transcodeAudio` when the browser refuses) and cut at pauses by `splitForTranscription` with `maxSeconds` one below the part length (the planner may run 1 s over). Part lengths 1/2/5/8 min (default 5): 8 min of 16 kHz WAV is about 20 MB of base64, under the 25 MB body limit most providers have. Per-model limits are in `model-support.ts`: AssemblyAI 110 s; Muse Voice Transcribe 590 s and WAV only. Cut parts are kept per source and part length for retries and re-runs; a retry whose parts do not fit the current model is refused with the reason (`partsUnfitFor`).
- **Runs:** two parts in flight (`runItems`). A failed part is never retried automatically (a paid POST that may have billed); its Retry is a new run booking only those parts. Standard pattern with these names: `replayArg` replays only parts without a result (`pendingOnly`; a transcript for another recording, or none, replays as the plain run), the part shows `failureLine`, Retry goes through `retryGate.retryFailed`. A retry uses the options of the run its transcript belongs to (`runOptions`: language, timestamps, speaker labels, vocabulary), not the current form, so a transcript never mixes them. A new run cuts the audio BEFORE it replaces the transcript, so an undecodable recording leaves the last transcript and its edits alone; it asks (`ui.confirmDiscard`) before replacing edited text or speaker names, which are held as work until copied, downloaded or sent. A recording whose length the browser could not read is cut before `beginRun`, so the run books its real estimate (and the per-run threshold applies); nothing is sent or booked if declined.
- **Merging** (`transcript.ts`, rules in its header): each part's offset is added and times are clamped to the part. Parts share no audio, so words said twice across a seam are real and stay; a repeat is dropped from the later part (words included) only when the model's own times overlap the next part's and the repeated words (at most 6, compared without case, Latin accents or punctuation) fit inside the overlap (0.1 s tolerance; untimed or non-adjacent parts are never compared). A segment running past the next part's first one is trimmed. Speaker labels are per request, so with several parts keys are `<part>:<label>` and the editor says to give one person the same name in each part.
- **Model table** (`model-support.ts`): no timestamps for GPT-4o transcribe and MAI-Transcribe 1.5 (docs); speaker labels only through `diarizationRoute` and with timestamps (the note says "needs timestamps" for MAI-Transcribe 1.5, not "unsupported"); vocabulary (`keyterms`) is sent only to `deepgram/` and `assemblyai/` (nothing documents the others; unsupported means a 400). The vocabulary field is the `tool-prompt` and stays editable; switches the model cannot honor keep the user's choice (`wanted`) and show off and disabled with the reason.
- **Recording:** MediaRecorder (WebM/Opus, else Ogg or MP4) in 1 s slices, 2 h at most; the recording is a session result (leave guard) and replacing one not downloaded asks first. The sample is `sample-speech.mp3` (the 13 KB Kokoro fixture), fetched on `?sample=1`.
- **E2E:** the microphone is a stubbed `getUserMedia` (oscillator into a `MediaStreamDestination`), so the spec runs in every browser. The 60-minute gate builds its WAV in the page and the mock answers each part with part-relative times.

## Audio tools: Text-to-speech, Music generation

- **TTS parts:** about 60 s of speech per part (`chunkLimit`: about 900 characters Latin, 420 Hangul, 300 CJK, fewer below 1x speed; capped at 3,000 for Seed Audio and twice a small model context such as Kokoro's 4,096 tokens; within Seed Audio's 120 s output cap and the providers' 60 s timeouts). Split at paragraph, sentence (`Intl.Segmenter`, CJK included), clause, word, then grapheme boundaries and packed greedily; a paragraph that fits is never split (10,000 words is 60-odd requests). Parts are MP3 except PCM-only models (`defaultSpeechFormat`: Gemini TTS), whose PCM is wrapped as WAV at the Content-Type's rate (24 kHz if absent). All parts are joined once with `stitchAudio` into the format chosen now; a joined MP3 decodes to within about 3 ms per seam of the parts' summed length (encoder padding), a WAV join is exact (both asserted by the gate).
- **TTS retries are the user's:** parts that failed or that Stop left unmade stay in memory with the made ones; "Retry"/"Make the other N" is a new run for just those (`prompt: ''`, so no Recent entry). The tool never retries a part itself (a 5xx may have billed); a failed part shows `failureLine` and Retry asks first when its request may have been billed (standard pattern). Voice previews are runs too (`prompt: ''`), cached per model, voice and speed as object URLs for the session.
- **Paid parts are reused, never dropped silently:** a new Read aloud builds its plan from the previous one and takes over every part made from exactly the same words with the same model, voice and speed (`newPlan(…, previous)`), so editing one paragraph remakes that part only (the title says "Continue" only for the same words; edited words are their own Recent prompt). Paid parts that cannot be taken over are asked about with `ui.confirmDiscard` before anything is sent; a refused run or a "no" changes nothing. Retry, "Make the other N" and Join again use the format chosen now (the one setting that changes without remaking a part). Made but unjoined parts are held as work (`ui.holdWork`).
- **TTS speed** shows only for models listing `speed` in `supported_parameters` or in a family known to take it (`SPEED_MODELS`: Seed Audio, Voxtral, Kokoro; Kokoro unverified through OpenRouter). Voice cloning (`input_references`) is not offered.
- **Music variations** are one run with one streamed request each (`runItems`, all at once): one History entry and one budget decision; the estimate is the flat price times the count (three Clips, $0.12, open the default $0.10 per-run confirmation). The Clip/Song radios write the tool's model binding (`setToolBinding`) and are disabled during a `?model=` visit. A target length is cut with `trimMedia` (2 s fade, 192 kbit/s like Lyria's MP3s); a failed or stopped cut keeps the paid song whole. A target longer than the model's song (`LENGTHS[].seconds` plus 25%) is said under Length. Pro's timed lyrics carry only start times: a line ends at the next line's start unless a section marker comes between (an instrumental passage may follow), then after the song's median line gap. File names carry local time (`fileStamp`).
- **Music retries:** the card's Retry and the toast's are one run of the variations asked (`RetryArg.retry` is a list); the toast's `replayArg` sends only variations without an answer (a finished song, or an answer without music, counts as answered). "Answered without any audio" is a `NoMusicError` like a refusal: billed, says so, no Retry. A form with nothing in it (no description, style fields, lyrics or image) is not sent.
- **E2E:** the 10,000-word TTS estimate (about $0.25 at Kokoro's priciest endpoint) opens the budget confirmation, which the gate accepts.

## Image tools: Image generation, Image editor

- **`POST /images` only** (the chat route needs $1 of key balance, docs/openrouter-api.md §0). `imageModelControls()` (`src/core/models/image-params.ts`) turns `GET /images/models` into what a model takes; a field it does not list is never sent (a 400). Forms keep every user choice and send only what the current model takes. One policy for every image tool, `models.imageControls(id)`: listed → `ready`; list read but model absent → `missing` (refuse before the run); list unreadable or empty → `unknown` (bare controls, only the prompt is sent: let the request try). A failed read is retried after 30 s (`IMAGE_CONTROLS_RETRY_MS`) and on `models-refreshed`, never latched. A zero catalog image price is unknown, not free (`estimateImage` returns null).
- **Several images (generation):** one request with `n` when the model's `n.max > 1`, else one request per image (`runItems`, three at a time) with `seed + i`, or a locked seed repeats one picture. The run's seed is drawn before `beginRun` but written to the field only after it (a refused run changes nothing). Failed cards and Retry are the standard pattern (Shell and UI). A Stop keeps completed images (`partialImageResult(error)?.images`) as cards; the rest is a stopped card with Retry. An exact size is compared as numbers ("1024 x 1024" is the listed `1024x1024`); a size the model does not list is explained in the form's notes, never dropped silently. Card action "Variation": one new image, new seed.
- **Masked edits:** there is no mask parameter, so `input_references` are [the picture with the mask tinted magenta at 50% (`maskOverlay`), the plain picture, the mask as a black/white PNG], cut to the model's `input_references.max` in that order, with an instruction naming only the references actually sent. They are built from the decoded, upright pixels at one common size (<= 2048 px). `aspect_ratio` is the offered one closest to the canvas; `output_format` is PNG when offered. A result of another aspect is fitted and centered (never stretched) with a warning. "Keep outside the mask" composites through `featherInside(mask)`, a box blur clamped to the mask, so outside pixels stay the original exactly. Outpaint puts the picture on a gray canvas whose new area is the mask; its soft edge sits on the picture's side of the seam, so the gray never blends into generated pixels. Pictures over 16.7 MP are scaled down on load (compositing stays full size); only the version on screen stays decoded.
  - **Busy from the press:** `editing` is set before the pictures are prepared and before `beginRun`, so loading, version changes and painting wait while the budget question is open too; every path out resets it.
  - **The paid answer is never lost:** after `api.images`, keeping the outside falls back to the model's own picture, an unreadable size to the canvas's, a version that cannot be drawn stays in the strip with its card (error shown), and a Stop keeps a picture already made as a version.
  - A version's Remove asks while it is not downloaded and is refused while an edit runs (`beforeRemove` composes `busyEditing` with `confirmUndownloaded`).
- **Mask undo** replays strokes from blank (`replayOps`), no snapshots; after an inpaint version the mask is cleared as one undoable step. Versions are `imageResultCard({ viewer: false })` session results (the canvas shows the picture); only the working version's card is in the page.
- **Received files wait for the model's limits** (generation: `?receive=` and drops go through `whenReady`, which waits for `/images/models`), or references would be refused as "no room".
- **`.vstack` inside a tool's input zone grows:** Bootstrap gives it `flex: 1 1 auto` and the input card body is a flex column stretched to the output's height, so it opens a gap when the output is taller. Use `d-flex flex-column` for direct children of `ui.input`.

## Isolated image (`src/tools/isolated-image/`)

- **Adaptive threshold** (`adaptiveThreshold` in `src/core/media/image-pipeline.ts`, via the `adaptThreshold` option): edit models answer on off-white (240-252) with noise, which at a fixed 245 counts as content (the box becomes the whole picture, specks survive the fill). The background is the **lightest** population on the picture's border (around its 90th percentile, read twice), never the border's median: a pale product covering most of the frame would otherwise set the threshold to its own value and be erased while the QA passed. The threshold is 7 median absolute deviations plus 3 below that background (about 6σ: noise and a soft shadow's faint tail stay under it) and at least 3 above the lightest darker population on the border (a product reaching the frame stays content). It is never raised: a flat 251-and-up background keeps 245. When the background holds under a quarter of the border, is darker than 200 (`MIN_ADAPTIVE_THRESHOLD`) or overlaps a pale product, the fixed threshold is used and `backgroundUnclear` fails the QA ("check this one"). Automatic is the default per photo; a threshold set in the review is used exactly.
- **Despeckle** (`fillAndDespeckle`, `despeckle` option): a soft shadow fading through the threshold inside noise leaves gray specks that widen the product box and stay as dots. So the background is filled on the model's picture first; pixels the fill did not reach are grouped through corners too (8-neighbor: a diagonal line is one group, and one touching the product joins it), and only a **speck** becomes white: at most 64 pixels, at most 12 long and no more than three times as long as wide, nothing more than 40 below the threshold, no such darker pixel within 3 px, off the picture's edge. Then the box is found. Fixed small limits, not a share of the picture: a share erased 1-px diagonal lines, threads and beads, and noise specks do not grow with the picture.
- **JPG border:** JPEG codes 16 x 16 blocks and the decoder smooths chroma across them, so a block holding product tints its border pixels. A JPG keeps at least `MIN_JPG_MARGIN_PX` (24) of white (`appliedMargin`; the review shows "0.5% (JPG uses 1.2%)"), and every exported JPG is decoded again and its border counted (`encodedBorderFlaws`), which the QA reports. PNG keeps any margin.
- **QA** (`qa.ts`) is `checkIsolated` on the square (border exactly #FFFFFF, product off its edge) **plus** the product box against the model's picture edges: the margin padding alone makes the first check pass, so the box reaching the picture's edge is what catches a product cut off by the frame, or a background that was not white (box on all four edges).
- **Results follow the current settings:** each photo keeps the model's answer (`edited`, paid for); `processingKey` (size, margin, threshold and whether automatic, sharpening, format, JPG quality) tells when its result is stale, and `reconcile()` remakes it in the worker, never with a request (`PROCESS_SLOTS` = 2 jobs in flight; a newer job for a photo supersedes its older one). Review controls, settings changes, a run's end and a Stop after a paid answer all go through it. A result is named when committed (pattern at that moment, format and size of its Blob); a later pattern change renames (a new card for the same Blob, keeping "downloaded").
- **Result cards** are `imageResultCard` with `viewer: false`; the tool's thumbnail, badges and QA reasons go in its `extra` part, redrawn in place; Review, Edit again and Another model are its `actions`. Only the file as it is is offered (`formats: []`): its JPG border was checked after encoding, a canvas conversion's would not be. Remove drops the photo with its result (`confirmRemoval` asks first when it was not downloaded, and says so). The list and grid show `imageThumbnail` copies (144 px, 288 px), never the 2000 px result; a photo's change redraws only its own row and card.
- **Promptless** (`promptless: true`): the instruction is fixed; a note could only weaken "keep the product unchanged, remove everything else". Prompts saves settings presets; History keeps the settings and one QA line per photo.
- **Runs:** Isolate sends only photos without a result; Retry and "Another model…" are new runs for those photos (`runner.trigger({ keys, model })`, booking that model's estimate); a new answer resets the photo's review choices. The error toast's Retry is `replayArg` with `pendingOnly(madeByLastRun)`: it skips photos the failed run already answered (`photo.editRun`), so a 402 mid-retry never pays twice, while "Edit again" on a photo with an older result still sends it. `n: 1` and `output_format: 'png'` go only when `ctx.models.imageControls` lists them; `missing`, or a reference range that cannot take one picture, is refused before the run; `unknown` sends the photo and instruction only. The estimate is one edit per photo uploading its photo once (`references: 1`, `requests`), the answer as large as the largest photo sent (`readImageSize` reads the header).
  - **A paid answer is never paid for twice:** if post-processing fails after the answer (in a run, or when a review or settings change redoes it), the answer stays in `photo.edited` with `processFailed`, and the card offers "Finish again, no new request" (`reprocess`, a free redo) next to the paid Retry. Isolate and "Retry not isolated" finish such photos for free (`keptAnswer`, `toSend`) and send only the others. A Stop keeps an answer already made (`partialImageResult`); the run's end finishes it through `reconcile`.
  - A possibly billed request shows `failureLine` and its Retry asks first (standard pattern); "Another model…" is a new request by choice and does not ask. The bulk button "Retry not isolated" covers failed and stopped photos alike.
- **Review:** the before/after wipe (`compareSlider`) compares the letterboxed original with the result, so the product does not line up (the model reframes it); side by side is the view for logos and text. A verdict that turns, or a result being remade, is announced politely.
- **E2E gate:** photos and isolations are drawn in Node (`tests/e2e/isolated-image-photos.ts`, own PNG encoder); the mock finds a request's photo by its data URL, because photos under 1024 px and 4 MB pass through `toDataUrl` untouched. Exported JPGs are decoded in the page and checked pixel by pixel.

## Video studio (`src/tools/video-studio/`)

- **One clip = one run = one persisted job.** Generate (and every sequence step) begins a run with the form as pressed, sends `POST /videos`, adds the job (`running`) and `run.handOff(job.id)`s at once, so Generate is free again and leaving is safe. The `video` job handler only polls (`pollInterval`: 2 s growing to the documented 30 s) and succeeds with the completed status's cost as `usage`, which the core books on the run before the job turns final; the video is downloaded at delivery, not in the poll. Whichever tab sees a job final delivers it once: `runs.reattach` ends the run, and the clip is placed and its sequence step settled in ONE locked store step (`delivery.ts`; idempotent; `repairSlots` repeats it on load); the job's payload is then marked `delivered` (a clip the user removed never comes back). A download answered 404 marks the clip `expired` (cost stays booked; never offered, joined or fetched again). A remote failure is an `OrError`, never a bare Error (History would read "Something went wrong"). "Stop waiting" ends the run with `run.cancel()` (aborted at once, booking the reservation; the job may still finish and bill).
- **No video request is ever sent again by itself.** `outcomeUnknown` gets the framework's toast without Retry (its OpenRouter activity link is the check: a POST without an answer has no job id to look up). A request OpenRouter accepted that the page cannot follow (no job id, job not stored) is shown by the tool without Retry (`markSent`, `billedBy`). The runner's Retry always repeats a clip (`replayArg`), whatever tab shows by then.
- **Persisted state** (`store.ts`): the timeline and the sequence run are JSON in `ctx.state`, changed only by read-modify-write under one Web Lock (`ortoolbox:video-studio:state`); every tab re-reads on `tool-state-changed`. Videos are memory-only: after a reload generated clips are downloaded again while OpenRouter keeps them (retention is known only to be >= 18 min, docs/openrouter-api.md §7.4); uploads are listed as "add it again". `forget()` aborts a clip's download; nothing of a removed clip is kept or registered again.
- **Form edits reach the stored run field by field** (`SpecEdit`, `applySpecEdit`): only fields this tab's user changed (a prompt or role per step, style, cap, failure rule, a step's image count); typing is debounced and flushed before Start, Resume, Re-run and blocker answers. Every change of the stored run (here or in another tab) is read back into the form with this tab's unwritten edits on top, so a stale form never writes over the run. While a sequence runs, prompts, roles and style are read-only; cap and failure rule stay editable. A step with fewer pictures than its count (lost in a reload) pauses with an `images-lost` blocker.
- **Sequences:** `sequence.ts` holds the pure rules, `sequence-runner.ts` the side effects (injected dependencies, unit-tested with an in-memory store). `plan()` decides what starts (chained one at a time, independent up to `MAX_PARALLEL` = 3) and stops before a step that would pass the spend cap. Spent means billed or maybe billed (shown "≈"), as the run books it: a known cost, else the reservation of an unknown cost, an `outcomeUnknown` or accepted-but-untracked send, an abandoned start, a "Stop waiting", a job the core gave up on; a job the provider failed (`failureKind: 'remote'`) counts nothing.
  - **Claims:** slots are claimed under the lock with the claiming tab's id (each tab holds a life lock `ortoolbox:video-studio:tab:<id>`), and the start re-reads the stored run after every await: Pause, Stop, another tab or the cap hand the claim back with nothing sent (`returnClaim`; `releaseClaim` for errors never turns stopped into paused). `recover` (page load, bus changes, becoming visible) settles `starting` slots whose tab is gone: adopts their job, else fails them as maybe billed and pauses.
  - **A start past its last check is never aborted:** `abortStarts()` (Pause, Stop, a failed step under "stop") aborts only starts that have not passed their final `verdict`; after it the start is `committed`, so the paid POST in flight finishes and its job is tracked. The final verdict also refuses a start whose signal aborted while the run was read. Stop keeps unsent steps so Resume can send them (New sequence abandons them).
  - **Failures:** a failed start follows the failure rule; errors that need the user (no key, locked, free-only, budget) pause and are presented. A chained step whose clip to continue is gone (removed, lost upload, expired) is never sent from its prompt alone: a `source-missing` blocker offers another clip, no first frame (`chooseSource`), or a re-run of the step before.
  - **Re-run:** each is a new `attempt` carried by its job, so a late job of an old attempt never settles the new one; its take replaces the old in place (left out of the join) and the chained clip after it is marked `staleSource` (its first frame is no longer dropped; the step shows "re-run it").
- **Frames win over references** (API: with both, frames are used): the form shows only the inputs of the chosen mode, and a chained step that starts from a frame can take only a last frame; a last frame alone is refused (`LAST_FRAME_ONLY_MODELS` is empty). Continue captures the true final frame (`captureFrame('last')`) as a PNG data URL (kept PNG under 4 MB); the clip goes right after its source with "leave out its first frame" on. Native extend sends a public `https://` link as a `video_url` reference only to models priced "with video input" (Seedance); otherwise it falls back to Continue and says why. `PREVIOUS_JOB_MODELS` is empty: grok and Seedance mini reject `previous_job_id`, and no model is confirmed to take it. Extend, Continue and Frames are off for a clip that is not ready.
- **Budgets (owner decision):** a sequence asks ONE question at Start for its total estimate (every step x repeat): `ctx.runs.approveGroup` with the sequence id as group and the cap as note; a block throws `BudgetBlockedError`, and a declined Start (`RunCancelledError`) stores and sends nothing. Its non-forced steps then begin with `useGroupApproval` (no dialog of their own, each still reserving its own estimate; the approval is stored, so it holds after a reload and in other tabs). A Re-run asks for itself. New sequence, and a Start that replaces a finished one, release the old approval (`releaseGroup`). Start refuses to overwrite an active stored run (another tab's). Estimates add Grok's per-image input price for frames and references (`estimateVideo` `images`).
- **The spend cap must never lift:** the field refuses 0, a negative or an unreadable amount with an inline error and keeps the stored cap (empty is "no cap"), so 0 never reaches the stored run, where it used to be read as no cap.
- **Nothing is fire-and-forget without a catch:** every store write started by a button, timer or bus event goes through `background()` (a failure is presented, and a timeline change the page had already drawn is read back); a paid clip that cannot be placed is presented with a Retry (the job is not marked delivered, so the next page start places it too); a null `reattach` is silent only when History still has the run, else it is logged and announced. **System pauses are announced** (`noteFinish`): any change to paused, stopped or done the page did not make in front of the user, and a new blocker, goes to the live region.
- **Rendering and focus:** the timeline is rebuilt only when its signature changes (a rebuild moves the `<video>` players, which pauses them), and the source selects only when their options change (a rebuild closes an open list); only usable clips are offered as sources. Reorder buttons at the ends are `aria-disabled` (focus stays after a move); trims show the stored, clamped value with `aria-invalid` and a note. Join moves focus to Stop and back; the frame grabber returns focus to its opener and steps by the clip's own frame rate (`video-fps.ts`, 30 fps when unknown), its last position being the true final frame. The join runs `concatVideos` (multi-threaded when the page is isolated; refuses more than `MAX_JOIN_BYTES`) with its own Stop. A joined video is a `videoResultCard` (`covers` its clips, so its download counts them as saved).
- **Notifications** follow the drawer switch: a one-clip job passes it as `jobs.add` `notify`; sequence steps pass false and the tool shows one notification when the sequence ends (the core's `'group'` notification would fire after the first chained step, which has no open job after it).

## Model arena (`src/tools/model-arena/`)

- **The contenders are the models** (`"ownModels": true`, see Shell and UI). The form (2–4 contenders, system prompt, temperature, Max tokens, blind, PDF reader) is the snapshot and is also kept in the tool's options; files are not in it (bytes stay in memory). A first visit picks distinct free text models (`defaultContenders`: preferred defaults, then the newest free model of each other provider; paid ones only to reach two).
- **A round** is one run per contender, begun together by `ctx.runs.beginAll` (`groupId` = the round's id, label "Model arena round: N models"): one budget question for the summed estimates (models and PDF add-ons), each run reserving its own, all or none. A refusal (Cancel, a block, Stop) withdraws the runs already begun: nothing is sent or booked ("The round did not start: nothing was sent."). Missing inputs, a prompt too long for a model and free-only (any contender or the parser paid) refuse the round before anything is booked.
  - **Timing and snapshot:** first token and total are timed from `onSend` (after the free-model throttle and retry backoff). Input, settings and files are taken when Compare is pressed (`input()`), never after planning or the budget dialog: a file dropped meanwhile belongs to the next round.
  - **Max tokens** is clamped per model (`fitFor` over core's `fitContext`) and is what estimates assume; unset, nothing is sent and estimates assume the model's cap, at most `DEFAULT_OUTPUT_TOKENS`. Files come in through `attachmentIntake` (noun "prompt").
  - **Retry** is the runner argument `{ kind: 'retry', index }` (stopped contenders too): a single run in the same group that asks for itself, with the round's own input (files stay while the round is on screen). From the press until it settles `round.retrying` closes voting and export (`allIn`). Every contender's request parses a new PDF, so a paid reader is charged per contender; the parser text then rides on the shared `AttachmentRef` and later rounds send it as text.
  - **Outcomes:** a failed `run.finish` is presented but the answer stays (never a failed panel). A refusal (`ChatStreamResult.refusal`) is that panel's error (billed, with Retry), never an answer.
- **Blind (default):** panels are shuffled (`order`) and labeled Model A–D. Before a vote or "Reveal without voting" nothing tells models apart: no names, no cost ($0 gives free models away), no "Cheapest", no panel letter in History (`run.finish` writes no meta). Errors use `failureText(error, { blind: true })` (true for any model, same `note`, activity link and Retry on every failed panel); each failed entry stores both wordings (`failure.shown`, `failure.blind`) and the real one shows after the reveal (an unknown outcome gets the activity link, no plain Retry). A hand-revealed blind round takes no vote. Speed metrics and "Fastest" show at once.
- **Metrics** (`metricsOf`, `summary` in `round.ts`): token counts come only from the stream's usage chunk (a stopped or cut stream shows "—", though the client books zeros); tokens/s needs 50 ms or more after the first token and is dropped when the count includes reasoning that never streamed; a full tie marks neither "Fastest" nor "Cheapest"; `finish_reason` "length" is marked as cut off. Costs use `formatRunCost` ("Free", "Unknown (≈ $x counted)").
- **Export** is offered once names show and every answer is in (`exportReady`). All model- and user-written text goes through `safeBlock` (`src/ui/markdown-safe.ts`, also Bot-to-bot's), so nothing can close a fence or forge a "## Vote" section.
- **Tally** (`tally` in tool state, written only through `ctx.state.update`): a model counts once per voted round in which it answered (rounds, wins, ties, "All bad"), even in two panels (allowed on purpose). Reset reads the tally as stored inside the update; Undo adds that value back to whatever was voted since.
- **`?model=` (History's "Re-run with another model"):** each contender run's settings hold the whole round, so the round reopens and the override replaces the contender whose run was opened (setup reads the `?run=` record before the framework's `applyState`); without a round of this tool it replaces contender 1. Saved like any form change.
- **Rendering:** panels are built once per round and updated in place (the stream owns the answer); a panel's error block is rebuilt only when the error changes (a focused Retry survives other contenders finishing); the tables redraw only rows. The answer is a focusable, scrolling region (28rem).
- **E2E:** the mock answers SSE in one piece, so the gate spec holds every chat `fetch` in the page until four are waiting.

## Decision (`src/tools/decision/`)

- **Two pure modules decide everything:** `schema.ts` (form data, validation, the request) and `results.ts` (reading a response, confidence, verdict, percentages); the builder, situation panel, library and results view only draw. A `QuestionDef` is flat (a question's Yes/No criteria, options and levels at once) and `wireQuestion` sends only the active type's, so switching type loses nothing typed (the image tools' policy).
- **Ids are slugs; three keys are not allowed.** The wire id is `slugify(name)`, made unique (`name_2`), and follows the name until the user edits it (emptying it hands it back). `wireId()` (trimmed id) names a question in the request, validation and answer lookup, and `toDef` trims too. `parseJsonSafe` deletes `__proto__`, `constructor` and `prototype` keys at any depth, so an answer under such an id or a probability under such an option name would never arrive: `uniqueId` skips them and validation refuses them.
- **Confidence has three sources.** Yes/No (`noul` is P(yes)) has none on the wire, so it is `max(p, 1 - p)`; Choice and Score use the API's `confidence`, else the highest probability, else nothing, and no confidence is never "Clear". Mercury and Jev differ in key order and rounding: `results.ts` never depends on order, ignores unknown keys and answers for unasked ids, and turns a missing or unreadable answer into a `none` card instead of throwing.
- **The badge is decided on the number shown.** `formatPercent` cuts (not rounds) to a tenth of a percent (83.9%, never 84%) and `verdictOf` compares the same whole tenths with the threshold, both with an epsilon of 1e-9 on `p * 1000` (`1 - 0.07` is 0.9299999999999999: an exact comparison put it below 93% beside a card saying "93%"; 0.9999999995 must not read "100%"). A threshold change edits the shown badges in place (`ResultsView.relabel`): nothing redraws or animates, nothing is sent. Cards match thresholds by the builder row's key (`builder.keys()`/`thresholds()`), not by id, so a rename keeps the card attached; `run` relabels after `show()` for a threshold edited while the request was out.
- **Two token numbers for two jobs** (`tokens.ts`). The price estimate inflates the whole body by 1.8 (core's count gives 269 tokens for the tutorial request; Jev billed 476, Mercury 253). The context check, which refuses before `beginRun`, counts the situation's prose as prose and inflates only the structure, so about 120,000 characters still fit a 32,000 token context: a refusal must not lean high like a price. Context is the catalog's `contextLength`, else `DEFAULT_CONTEXT_TOKENS` (32,000).
- **Problems show only for touched fields** (changed, or named by a failed Run). `showProblem` (`invalid.ts`) leaves a message already on show alone (it would be announced again); the first problem takes focus; Situation is checked before Questions.
- **The snapshot's `prompt` is what is sent:** the text block in text mode, the `name: value` lines in fields mode (`promptOf`), so Prompts, History, search and Recent describe the run. `settings` = `stateMode`, `fields` (as typed, blanks included), `questions`, and in fields mode `text` (the block kept behind the fields, never sent). `applyState` leaves questions or fields alone when the snapshot has none; lists the user emptied stay empty (validation flags them). A drop or send that adds nothing (every file over 1 MiB or empty) changes nothing, not even the mode. The run's output is `JSON.stringify(response.answers)`; Download/Copy is `{ model, answeredBy, state, questions, answers, usage }` of the last run.
- **Saved deciders are one tool-state key each** (`decider:<uuid>`), never one array, so two tabs cannot overwrite each other; Undo of a delete writes back the same id; the list follows `tool-state-changed`; a rename is `renameDecider` through `ctx.state.update` (only the name changes, a delete elsewhere stays deleted). Choosing in the list loads nothing (arrowing through a closed select would): Load does, and asks when it would lose something (`lossOnLoad`: questions differ from the last loaded or saved `baseline`, or the decider brings a different situation). Saving the situation is opt-in (default off: private text); a used name asks before replacing.
- **The scale:** levels are numbered from 0 like the API's `score`, a position (1.99 sits near level 2), drawn as a marker with a tick per level; probabilities are also text and the drawings `aria-hidden` (one `role="img"` with a full label). Move up/down buttons reorder options and levels (the keyboard route; focus stays on the moved item); levels can also be dragged from an untabbable handle, with a payload type of its own (never `text/plain`: a text field would take it in), and a drop clears the drag itself (`dragend` may never come after the redraw). Fills animate with `scaleX(var(--or-fill))` set after two frames; `_motion.scss` handles reduced motion.
- **The model picker's help** is `CAPABILITY_INFO.decisions.help` (Jev and Mercury Decide are the only models verified to accept this schema); free-only resolves to `inception/mercury-decide:free`.
- **Recording a paid answer never fails the run:** `handle.finish` is outside the `try` (as in the arena): a failed write is presented, the answer stays "Done", no Retry (it would pay twice). A loaded template and the sample start at the drawer's threshold (`templateQuestions(id, threshold)`); the review count has one wording (`reviewCount`).

## Bot-to-bot chat (`src/tools/bot-to-bot/`)

- **One run per press:** each Start, Resume or Step is one run (`models: [A, B]`, `groupId` = the conversation's id), booked at min(cost cap minus spent, the dearer speaker's per-turn estimate × turns left). The estimate assumes every turn uses Max tokens and the prompt grows by one full reply per turn; an unknown price books the cap left. With the default $0.25 cap a paid Start is above the $0.10 per-run threshold, so Warn mode confirms it: intended. The run checkpoints the Markdown transcript after every turn (History's replay). Everything is checked before `beginRun` (an open, changed editor; opener; distinct names; the other tab; a too-long next turn; the limits), so a refused run changes nothing.
  - **Numbers** are committed at the start of every run (Ctrl/Cmd+Enter has no blur), not per keystroke (typing "25" over "20" would briefly set a limit of 2). Names, personas and models are fixed at run start; limits are read live (raising one while paused lets Resume go on). A Pause pressed before the loop starts holds after the first turn; cleared when the runner goes idle.
- **Failed turns:** a reply with no text is a failure (a reasoning model can spend its whole budget thinking), never a silent re-ask. A refusal (`ChatStreamResult.refusal` or a content filter) is that turn's error ("Bot A declined to answer: …"), billed once. A failed turn stores `failureText(error).text` and `outcomeUnknown` and is marked presented (the turn is the presentation; errors that `needsAction` still go to the runner, whose Retry resumes); one that may have gone through shows the caution and the activity link instead of "Resume to try again". Resume is always the user's. Turn costs use `turnUsageLine` over `usageLine`: an unknown cost reads "cost unknown (≈ $x counted)", `x` being the turn's estimate kept in `costUsd`.
- **Stop conditions** live in `loop.ts` (pure, fake-timer tested). After a turn: cut by time, stop phrase, cost, turns, time; before one: turns, time, cost (spent plus the next turn's estimate; an unknown estimate skips that part). The cap counts as reached only once something was spent, so a $0 cap still runs free models. The stop phrase counts only at the end of a message, ignoring case, trailing whitespace, punctuation, quotes and Markdown emphasis, with a word boundary before a word phrase ("done" ends "Well done." but not "undone"). The time limit is a timer aborting the turn's own signal (`chatStream`'s `signal`, combined with the run's), so the partial text is kept as `cut`; a limit changed mid-turn re-arms it (`onLimitsChange`) and `LoopEnd.limits` reports the limits that applied. Stop ends the conversation (`stopped`); an abort from elsewhere (pagehide) only holds it. A turn's own usage comes from a `Proxy` over the run handle that tees `addUsage` (`tapUsage`); an unknown cost counts as that turn's estimate.
- **Messages per speaker** (`request.ts`): own turns are `assistant`, the other bot's and the moderator's `user`. Moderator text (the opener too) is marked `[Moderator]`, and inside a merged user message every part is labeled with the other bot's current name (`[Bot A] …`), or the bot cannot tell who said what. Trimming drops the oldest entries after the opener (framing, opener and the entry being answered always stay) to core's `promptBudget`; `fitContext` decides too long and `max_tokens`; `trimmed` is recorded on the turn. Failed turns are a record only (not sent or counted, the same bot speaks again; empty ones are dropped on Resume); Resume carries on after end markers. Editing removes everything after the entry (Undo only while the edited entry is still last and unchanged); an edited cut turn counts as finished.
- **Persistence and tabs:** one conversation in tool state (`conversation`); every write bumps `rev` and sets a new `writeId` (two tabs can write the same `rev`), through one queue. A turn left `streaming` by a reload keeps its text as `stopped` (or goes when empty), so it comes back paused. One Web Lock for the whole tool, `ortoolbox:bot-to-bot` (`holdLock(…, { ifAvailable: true })`, probed, never waited for; not per conversation, since New conversation gets a new id), held by the running tab and briefly by any tab changing the conversation (moderator message, edit, New conversation, Undo); while another tab holds it these are refused with a toast. After taking the lock a run re-reads the store and, if another tab changed it, shows that version and stops ("press Resume to go on"). An idle tab with no write pending shows whatever is stored (`writeId` differs); a change announced during a write or run is looked at afterwards (`followStale`). A data reset bumps an `epoch`: queued writes from before it and the conversation in memory are dropped, and the store refuses an old write that reaches storage after the wipe (not shown); reading the key again re-arms it, so the next conversation is stored without a reload. Writes are plain `set`s of a copy: the tool lock already serializes writers, so `state.update` would add nothing.
- **A streaming turn is stored while it speaks** (words so far at most every `PARTIAL_WRITE_MS`, 1.5 s, with a run checkpoint), so a reload or crash keeps them as a stopped turn. Its cost is not counted until the turn ends. A turn cut by a reload is booked by the run sweep, and the conversation settles with it: it lists the runs it began (`openRuns`, each with the `countedUsd` already in `spentUsd`, closed when the page ends the run itself), and on the next load, or as the sweep finalizes the run (History subscription), `settleOpenRun` adds the ledger's `bookedCost(record)` beyond what was counted, never lowering the total; a run record that is gone leaves the total marked approximate. It settles under the tool's lock, and a still `running` record waits.
- **Loaded setups** (`applyState`: Prompts' Use, History, `?prompt=`, the sample) change the form for the visit only; only a field the user changes is saved as an option (`saveParams(key)`). A setup with another opening prompt than the open conversation's sets it aside (Undo brings it back). On a `?model=` visit Bot A gets the visit's model, B keeps its own. Each bot has its own picker; a bot without one uses the default text model.
- **Run bar:** the runner's own (Shell and UI, "A bar with more than Run"): Run (`hideWhileBusy`) is Start or Resume (`runner.setLabel`), Step is `addAction({ run: 'step' })`, Pause is `addAction({ when: 'busy', onClick })`; Ctrl/Cmd+Enter is Start or Resume. The moderator box keeps Escape for itself, so it does not stop a run.
- **Markdown transcript** (`export.ts`, also History's replay): all level-2 headings (opening prompt, moderator, entries, `Ended · …`, `Totals`); bot and moderator text goes through `safeBlock` (closes an open code fence; escapes headings, rules, setext underlines and long HTML blocks outside code).

## Non-obvious decisions

- **Service worker = offline shell + cross-origin isolation + policy headers.** GitHub Pages cannot send headers, so the one service worker (`src/sw/sw.ts` wiring, logic in `src/sw/worker.ts`, unit-tested with a fake CacheStorage) adds COOP `same-origin`, COEP `require-corp` and CORP `same-origin` to every same-origin response it serves (multi-threaded ffmpeg.wasm needs them), and a `Content-Security-Policy` header to HTML documents (the meta policy plus `frame-ancestors 'none'`) and to worker scripts (`workerPolicy()`: pdf.js, ffmpeg's workers and the image worker otherwise run with no policy). Always `require-corp`: nothing is hot-linked, so `credentialless` buys nothing and needs per-browser negotiation. It never calls `respondWith` for cross-origin requests: OpenRouter calls go straight from the page.
  - **Isolation reload is opt-in:** `boot({ isolation: 'required' })` (Diagnostics and Video studio only) reloads once on a first visit when the worker is ready, guarded by sessionStorage `ortoolbox:isolation-reload` so it can never loop, and only if the user has not started using the page (no keydown/pointerdown/input/paste/drop, no pending results or held work); otherwise the next page is isolated anyway. It restores the address the page started with (`replaceState`) first, because tool pages strip `?run=`/`?prompt=`/`?sample=` once applied, and never reloads a `?receive=` page (a Send to hand-over cannot be repeated). Every other page only registers the worker and must never reload (the OAuth callback carries a single-use code). Without isolation, ffmpeg runs single-threaded.
  - **Caches** (all named `ortoolbox-…`: every project site on `ethanpil.github.io` shares one CacheStorage and can write to it): `pages-<build hash>` holds the HTML and un-hashed public files; `assets` (shared by builds, so unchanged files such as the 32 MB cores are not downloaded again) holds files under assets/ and vendor/. The worker's manifest (`__SW_MANIFEST__`, built by `vite-plugins/service-worker.ts`) records a SHA-256 for every page and asset. Entries are verified at install (a stale CDN copy is retried once bypassing caches, then fails the install; a failed install deletes only its own cache), at every fill and every time they are served; a mismatch deletes the entry and the request goes to the network. Serve-time verification of the 32 MB wasm costs about 0.2-0.4 s per ffmpeg start (measured), against seconds of compilation, so everything is verified, no exceptions. Files the build does not list are never served from the cache and are deleted at activation (that replaced "last used" stamps, which re-wrote whole entries daily). Precached at install: every page's eager closure plus every lazy JS/CSS chunk up to 512 KB (about 2 MB); pdf.js's worker, wasm, fonts and CMaps and the ffmpeg cores are cached on first use. Range requests bypass the cache; every cache call in the fetch path falls back to the network.
  - **Updates and deploy skew:** a new worker `skipWaiting()`s and claims open pages without reloading them; the next page load gets the new shell. Activation deletes only complete pages caches of *older* installs. A page still served from an old worker's cache finds its lazy chunks there. A tab on an older build after the new worker took over gets a 404 for a lazy chunk the host no longer has (the new worker cannot verify the old build's files): Vite fires `vite:preloadError` and `src/core/stale-build.ts` offers a reload in a toast.
- **Shared origin.** localStorage, IndexedDB, sessionStorage and CacheStorage are readable and writable by any other page under `https://ethanpil.github.io/`. Keys at rest are only as safe as every other project site on that origin; a custom domain removes the risk. The worker's hash checks stop one thing: a sibling page planting code in the caches that keeps running in ORtoolbox's pages after it is gone. They do not stop an open sibling page from reading or changing storage, unregistering the worker, or scripting an ORtoolbox window it opens.
- **ffmpeg loading (`src/core/media/ffmpeg.ts`).** `@ffmpeg/ffmpeg` always starts a *module* worker, so we ship the cores' ESM builds, self-hosted under `vendor/ffmpeg/core[-mt]-<version>/` (copied from node_modules by `vite-plugins/ffmpeg-assets.ts`, served by middleware in dev; versioned URLs are immutable). The page downloads the wasm itself (progress against the size recorded at build time, because Content-Length is the gzipped size on Pages) and hands it over as a `blob:` URL; core JS and workers load from same-origin URLs, so no `blob:` worker or script is needed. `optimizeDeps.exclude: ['@ffmpeg/ffmpeg']` is required for its worker URL to survive the dev server. Core start-up times out after 60 s; if the multi-threaded core fails or times out, the page uses the single-threaded one for the rest of the session. Terminated or crashed instances are never handed out again; `disposeFfmpeg()` frees everything. Its file system lives in its worker, not the wasm heap, and Chromium cannot allocate one 2 GiB buffer: joins are capped at `MAX_JOIN_BYTES` (1.5 GiB, peak about twice the result).
- **CSP** (`vite-plugins/csp.ts`, the single source, a reason per directive; a meta tag on every page plus headers from the worker): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self' https://openrouter.ai blob: data:; img-src 'self' blob: data:; media-src 'self' blob: data:; style-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; frame-src 'none'; form-action 'self'`. Tighter than PLAN.md: no `blob:` workers, no frames, no remote images or media (results arrive as base64 or are fetched from openrouter.ai into Blobs), no form posts to OpenRouter (sign-in is a navigation). `'wasm-unsafe-eval'` allows wasm compilation, not JS eval; ffmpeg and pdf.js compile wasm inside workers, which get their own policy, and pdf.js has main-thread fallbacks. **Framing:** nothing frames the site (a framed tool page could be clickjacked into a paid run via `?prompt=`/`?model=`). The worker's `frame-ancestors 'none'` rarely applies (browsers partition service workers by top-level site, and every `*.github.io` project is its own site, so a framed page comes straight from Pages), so `public/theme-init.js` hides any framed page (`display: none` on `<html>`) before first paint. No `'unsafe-inline'` for styles: Bootstrap/Popper set styles through the CSSOM, which CSP does not restrict. `build.assetsInlineLimit: 0` stops Vite inlining fonts as `data:` URLs (would violate `font-src`).
- **Dev parity:** the dev server gets a CSP meta tag from the same table plus only what HMR needs (`'unsafe-inline'` styles, the HMR `ws:` origin), and sends COOP/COEP/CORP via `server.headers` (and from the ffmpeg middleware), so dev pages are isolated without the worker and CSP violations show up in `e2e:dev`. `vite preview` sends no headers, like Pages. Specs that differ between the two read `isDevServer()`.
- **Theme before first paint:** `public/theme-init.js`, a classic render-blocking script (inline scripts are forbidden), reads `appearance.theme` (`light`/`dark`/`system`) from localStorage `ortoolbox:settings`, sets `data-bs-theme` and follows OS changes while the theme is `system`. It is the one sanctioned storage read outside `src/core`; keep its contract in sync with the settings schema. The View Transitions opt-in is CSS (`@view-transition` in main.scss), not a meta tag.
- **Sass, CSS size, icons.** `quietDeps` hides the deprecations inside Bootstrap. Bootstrap's partials cannot be `@use`d one by one (they share a global scope), so `src/styles/_bootstrap-subset.scss` is the one file of ours that `@import`s them, with the variable overrides above the imports; `silenceDeprecations: ['import']` in vite.config.ts is for that file only. It is bootstrap.scss minus breadcrumb, pagination, tooltip, popover, carousel and the clearfix, focus-ring, icon-link and vr helpers (none is rendered; add a line back if a page starts to). A tool's own rules live in `src/styles/tools/<tool id>.scss`, which `html-head.ts` links from that tool's page only (image-generation and image-editor share `_images.scss`); a class used by two tools or by `src/ui` belongs in the shared partials. Bootstrap's utility classes are not pruned (some are built at run time, such as `text-${tone}-emphasis`, so a scan cannot prove one unused). **Icons are a subset:** `npm run icon-subset` (`scripts/generate-icon-subset.mjs`, scan in `vite-plugins/icon-usage.ts`) finds every icon name that is a whole string literal in `src/` (not tests) or a `bi-` name in a class string, and writes `src/styles/_icons.scss` and `src/styles/fonts/bootstrap-icons-subset.woff2` (16 KB instead of 134 KB; cut with Python fontTools, hence committed outputs). An icon name built at run time is invisible to the scan: spell each one out. `tests/lint/icon-subset.test.ts` fails on an icon the subset lacks or a name the font does not have. The font keeps `font-display: block` (an icon has no fallback text) and is preloaded with `crossorigin` by the post hook in `html-head.ts`.
- **TypeScript 6, one compiler.** `typescript` is pinned to 6.x for tsc, ESLint, Vite and Vitest alike, because typescript-eslint does not support TS 7 yet (TS 7 ships no JS compiler API). Revisit when it does.
- **Remote media is fetched, not hot-linked.** Under COEP `require-corp` cross-origin `<img>`/`<video>` without CORP are blocked, and the CSP forbids them anyway. Load results with `fetch` → Blob → object URL. `connect-src` allows only openrouter.ai: if a result ever lives on another host (`unsigned_urls` may), use the openrouter.ai content endpoint or grow the CSP deliberately.
- **OpenRouter CORS** (checked 2026-10-02): `Access-Control-Expose-Headers` is only `X-Generation-Id,X-Provider-Name,request-id,cf-ray`, so browser code cannot read `Retry-After`; back off without it. The mock reproduces these headers.
- **Core services are factories** (`createApiClient(core)`, `createKeysService(core)`, …) that read other services from `core` at call time, never in the factory body, so the composition root can wire circular dependencies. Tests pass a partial core (`testCore()` in `src/core/api/test-fakes.ts`: real bus and settings, under `isolateChannels()`; `src/core/testing/state-fakes.ts` wires the state services the same way).
- **API client rules** (`src/core/api/client.ts`). Keyless catalog GETs send no custom header (no preflight).
  - **A retry must never pay twice.** Idempotent GETs retry 408/429/5xx/network failures; paid POSTs only 429, the in-flight 402 and 503 (OpenRouter certainly did not start them); chat only 429 and the in-flight 402; never a stream once its response started, never the auth-code exchange (`mayRetry`, `RETRY RULES`). Waits honor `error.metadata.retry_after_seconds`. An error inside a 2xx body of a POST is never retried (the provider had started: `midStream`); string error codes map to a status only by exact name (`statusFromCode`: a `/rate/` match once turned `failed_to_generate` into a retried 429).
  - **A maybe-billed request is never free.** A paid request that may have reached a provider without a known cost (network loss, abort, a stream without a usage chunk, a 408, a 5xx other than 503, an error inside a 2xx body) reports `costUnknown`, so the run books its reservation and keeps its group-approval share (a retry cannot spend it again), and throws with `outcomeUnknown`: `presentError` and the runner offer the tool's `safeAction` (or OpenRouter's activity page) instead of Retry. **Per endpoint (owner rule: decide from the docs):** only `/images` documents that a failed generation is not billed (docs/openrouter-api.md §3.4), so its error answers (5xx, an error in a 2xx body or stream event) book nothing and are not `outcomeUnknown`; a lost connection still is (completed images bill). Every other paid POST and chat has no such statement. **In flight:** before each request leaves, `run.sending()` stores `RunRecord.inFlight` (awaited; a storage failure never stops the request) and the client ends the mark once the usage is reported, so an orphan whose page died mid-request books its reservation instead of "sent nothing".
  - **Timeouts:** a stream that sends no bytes for 5 minutes fails as a dropped connection (`STREAM_IDLE_MS` in `sse.ts`; OpenRouter sends keep-alive comments while a model works), and a video status read gives up after 60 s and is retried as a network failure (`STATUS_TIMEOUT_MS`), so a hung read cannot hold a job's poll lock. A Stop during an image stream keeps the completed (billed) images on the abort error (`partialImageResult`) and books the rest as unknown (the provider bills images after a disconnect).
  - **Other:** `:free` requests are throttled to 20 per rolling minute through localStorage `ortoolbox:free-requests` plus an in-memory window (shared across tabs, approximate; a broken store never resets it). `CallOptions.onSend(attempt)` fires right before each fetch, after that wait and any retry backoff: time requests from it. A `noRetention` key adds `provider.data_collection:"deny"` unless every model of the request is free (it turns free ones into a 404), never on `/images` or `/videos`. TTS bytes carry no cost, so usage is estimated from the most expensive endpoint (`costEstimated`, or `costUnknown` without endpoint prices); video cost arrives only on the completed status read (`VideoJobStatus.costUsd`), which the job's `succeeded` result carries as `usage`. A chat stream's `delta.refusal` is streamed as text and named in `ChatStreamResult.refusal`, which also explains a reply ended by `content_filter` or `error` before any content (not in `text`): tools show it instead of an empty reply and never parse it as an answer.
- **Key lock:** every lock change rewrites `ortoolbox:keys` with one `setItem` and is refused (`KeysChangedError`) if another tab wrote meanwhile; backup and reset use `keys.exportFile/replaceFile/clear`, never the storage key. sessionStorage `ortoolbox:unlocked` holds `{key, at}` (raw AES key, last `touch()`), so auto-lock (capped at 24 h, re-armed when the setting changes) survives navigation between pages of one tab (a memory-only key would ask on every page). Browsers restore sessionStorage with a reopened tab or restored session, so closing the tab does not lock: auto-lock does (it reads `at`, so a tab restored later comes back locked), and the Privacy page and Settings say so. A session key that no longer opens `lock.verifier` is dropped at page start and before encrypting. A stored keys file that does not parse as version 1 (another version, damaged JSON, an unreadable lock) reads as no keys and is never written over (`KeysChangedError`, "reload"; Reset everything still clears it); entries of a v1 file this build cannot parse are written back unchanged, and lock changes are refused while there are any. Passphrases are NFC-normalized before PBKDF2; the strength hint scores by length (offline guessing), not variety. The first key added becomes `settings.defaultKeyId`; a null or stale id falls back to the first key. Removing keys also removes settings that point at them (default, tool bindings, per-key budgets). OAuth refuses with `KeyLockedError` (or `StorageUnavailableError`) before consuming the code, so the callback page unlocks and retries. Once the code is exchanged it is spent: if storing the key fails, `complete()` throws `KeyNotSavedError` holding the key in memory with `save()`, and the callback page asks for the passphrase or offers Save again (never the same code again).
- **Models:** capabilities and free detection follow docs/openrouter-api.md §9 (free = id only; music = Lyria). Caches are stale-while-revalidate (one background attempt, a failure remembered for 5 minutes) and dropped on `data-reset`; `models-refreshed` is emitted only after the IndexedDB write succeeded (else two tabs refetch from each other in a loop). `ModelPricing.prompt/completion` are null for non-token units (TTS, STT, video, music); estimates read `pricing.raw` and endpoint prices with deliberately high heuristics (`src/core/models/estimate.ts`). A zero price is unknown, not free (only `:free` ids are free): an estimate whose every price is zero is null. References on image models without an input price cost one output image each; the tokens estimate takes `audio: { input, output }` to price that side at the audio rate. Shipped defaults and their reasons live in `src/core/models/defaults.ts`; re-check them when the catalog moves. `resolve(tool, cap)` applies the run override (`?model=`) and the tool binding only when `cap` is the tool's primary capability (`capabilities[0]`): a text model pinned on Chat must not become its vision model.
- **Media gotchas:** never use fflate's async API (`zip`, `unzip`, `deflate`): it spawns `blob:` workers that `worker-src 'self'` blocks, and fflate then never settles. Use `zipSync` or `zipFiles()` from `src/core/export`. Multi-threaded ffmpeg crashes on H.264 encodes with the default thread count; every `exec` must pass explicit `-threads` limits (`src/core/media/ffmpeg-ops.ts`). Import `src/core/media/pdf.ts` dynamically only (about 5 MB of pdf.js assets). Stitch TTS/audio segments with `stitchAudio()` (decode → PCM → encode once; `concatMp3` leaves seam gaps). Run heavy pixel work in the image worker (`isolateImage`, `maskOverlayAsync`, `maskToRasterAsync`, `featherInsideAsync`, `compositeMaskedAsync`; module worker, falls back to the page), never the pure raster functions on the main thread; the source is not transferred while a page fallback may still need it, a failed worker is recreated (the page takes over after three failures in a row); decode and encode with the browser's codecs (`createImageBitmap`, canvas `toBlob`), not pixel loops on the page.
- **E2E runs with service workers blocked by default**; only the `sw-*` Playwright projects allow them and run `tests/e2e/sw/` only. The app must work fully without the worker.
  - In WebKit, requests from a page controlled by a service worker bypass Playwright's `context.route`, so they would reach the real network. Specs in `tests/e2e/sw/` must not call OpenRouter and avoid tool pages (they read the model catalog from openrouter.ai). As a backstop, every project sends non-localhost traffic to a dead proxy.
  - Playwright's `setOffline()` in WebKit also fails requests the worker would answer from cache; offline specs use `startPrivatePreview()` (a private `vite preview` they shut down).
  - Playwright's Firefox build does not start on some Windows 10 machines ("side-by-side configuration is incorrect", `mozglue`): run with `E2E_SKIP_BROWSERS=firefox`; CI runs all three browsers.
  - The mock enforces OpenRouter's real CORS allow-headers list on the actual request and serves binary bodies; `mock.file()` serves `tests/fixtures/media/`. `mock.respond(method, path, fn)` answers from the request body (pages sent in parallel arrive in any order); `sseResponse(chunks)` builds a stream for it. It serves SSE bodies in one piece (`route.fulfill` cannot stream), so event parsing is tested but pacing is not.
  - WebKit behaves like Safari's defaults: Tab (and, in Playwright's Windows build, Alt+Tab) skips links, and a click does not focus a button. Keyboard specs Tab to buttons and fields (`tabTo()`), and focus-return checks open things from the keyboard. A background tab runs no transitions, so multi-tab specs `bringToFront()` the page they drive.
  - Playwright's WebKit on Windows crashes its renderer during cross-document view transitions, so the `webkit` project emulates reduced motion on win32 only; CI (Linux) keeps transitions.
- **Fixtures** in `tests/fixtures/openrouter/`: `*.recorded.*` come from real calls (paid probes); `*.documented.json` were written from the docs where no recording exists (error shapes, video polls, generation, key, image streams). Replace one with a recording when a key is available.
- **Core state services** (`src/core/{bus,settings,runs,budgets,stats,history,prompts,jobs,results,tool-state,backup,data}`) are each `createXService(core)` and read other services from `core` only at call time.
  - **Budgets read the local ledger** (`stats` rows, written when a run finishes), never OpenRouter's lagging `/key` usage, plus the `reservedUsd` (or spend so far, if more) of every `running` run (all tabs), read from small `kv` holds (`meta:run-hold:<id>`, `src/core/runs/holds.ts`) written in the same transactions as the record, never from the records themselves (up to 500 KB of output each). `begin()` checks and writes the reservation under the Web Lock `ortoolbox:budget`, so parallel runs see each other; a declined confirmation deletes the record. Runs on free models only with a 0/unknown estimate skip budgets. If spend cannot be read, the verdict is `confirm` (warn and hard). Stats survive "Delete all prompts and history"; only "Reset everything" clears them.
  - **Group approvals:** `runs.approveGroup(group)` checks a group (an arena round, a video sequence) once: key and lock, free-only over all its models and add-ons, budgets against its TOTAL with one dialog (`BudgetQuestion` `kind: 'group'`: label, models, total, note). Nothing is stored or reserved on a refusal. The approval lives in `kv` `meta:group-approval:<groupId>` as what it still covers (runs and USD; every tab, across reloads) until `releaseGroup`; a run with `useGroupApproval` takes its share under the budget lock and skips its own dialog while there is room (same key, models within the group's), still reserving its own estimate, and a hard block still refuses. `runs.beginAll(specs, { label })` begins runs that start together all or none: approved as one group, a refused member withdraws the ones begun (record and reservation deleted, nothing booked), the handles come back in spec order, and it honors a Stop that arrives after its last check (it aborts the runs it returns). Unknown member estimates are left out of the group total and counted in `unknownEstimates` (unknown add-on prices too): the dialog says "≈ $0.27 + 1 unknown", and budgets treat the total as a floor (a monthly limit the known part reaches counts as passed). `RunHandle.reservedUsd` is what a run holds (estimate plus add-ons); an unknown cost books `max(cost, reservedUsd)`, so tools pass that as `booked` to `formatRunCost` ("Unknown (≈ $x counted)").
  - **Unknown cost is never free:** a run whose cost could not be determined (and every orphan the sweep finalizes that had sent a request) books `max(actual, reservedUsd)`. `run.checkpoint({ output: () => text })` takes a function, read only when the throttled write happens (and by `finish()` without an output). An orphan books exactly its stored usage when no request was in flight (`inFlight` 0; it is complete), max(usage, reservation) when one was; a handed-off orphan books what its job's end stored, nothing for a remote failure, else the reservation (job gone or canceled). An orphan that sent nothing (no request, none in flight, never handed off) books nothing and its reservation is released; so does a live run that ends aborted having sent nothing (no stats row, History keeps it, its group-approval share goes back). A run that failed with an error still counts as one error run.
  - **Run lifecycle:** a live handle holds the Web Lock `ortoolbox:run:<id>` (fallback: a `kv` `meta:run-heartbeat:<id>` every 30 s). pagehide only aborts; it does no IndexedDB work (the page may be gone). `runs.sweep()` (boot) finalizes `running` records with a free lock (or a heartbeat older than 3 min) and no open job. Runs continued by a job call `run.handOff(jobId)` and are finished by the job's completion handler via `runs.reattach()`. The final record and its stats rows are one transaction that refuses an already-final record, so spend is booked once; a failed final write can be retried. Storage failures never block a run. A data reset discards live runs (no writes afterwards) and stops job polling, in every tab. `history.restore()` (Undo) never brings a record back as `running` (it arrives `aborted`) and never books stats again. **Work in progress is never deleted:** `history.clear` and `prune` keep `running` runs, and Settings → Data's deletions (`liveWork` in `src/core/data`) also keep open jobs, finished jobs whose run still runs, and the saved state of a tool with such work; they return what they kept (`DataDeletion`) for the page to say.
  - **Jobs** poll under the Web Lock `ortoolbox:job:<id>` (`ifAvailable`); other tabs retry at the poll interval and take over when the holder closes. Poll results are written read-modify-write and dropped once the job is final, so a cancel from another tab wins. `attempts` counts failed polls; a non-retryable error, 20 failures in a row, or still running 3 hours after it was added (`MAX_JOB_AGE_MS`, `JobHandler.maxAgeMs`; the client reads an unknown video status as pending) fail the job (`gave-up`); `KeyLockedError` pauses until `keys-changed`. Removed jobs reach subscribers as tombstones (`removed: true`). A job books its end on the run before turning final (`usage` from `succeeded`; the reservation on `gave-up`), in one write with the run's `meta.jobCostBooked`, so a tab that takes the job over never books it twice; `failureKind` separates provider failures (`remote`) from the core giving up. Notifications are opt-in (`notify`), and `run.cancel()` ends a handed-off run as `aborted`.
  - **Backups** wrap `core.keys.exportFile()` in a passphrase envelope (PBKDF2 iterations from files capped at 2 M); the rest of the file is plain JSON. Every record is validated; invalid ones are skipped and counted in the preview. Merge: only settings present in the file override (the old British `favouriteTools`/`models.favourites` are renamed by `migrateSettings` first); runs, jobs, prompts (`usedAt`) and tool state (`updatedAt`) are replaced only by newer copies (a tie keeps the local one), and runs/jobs never move back from final; times must fit a `Date` (0 to 8.64e15) or the record is skipped; stats keep the max of each field; keys merge only under the same lock (a merge never removes a lock). Replace wipes keys only when the backup carries keys, and keeps work in progress like Settings → Data (`liveWork`: running runs, open jobs, jobs of a running run, the `tool:` keys of those tools; the backup's copies of them are not written, the preview has a "Keep …" line, the set is decided again inside the write transaction). Imported `running` runs arrive `aborted`; settings pointing at keys this browser lacks are dropped. Import writes keys (`replaceFile` with `expected`) and settings, then all IndexedDB changes in one transaction, rolling keys and settings back if that fails. Wrong passphrase: nothing is imported.
  - **Tool state** (`ctx.state`): `update(key, fn)` is a read-modify-write under the per-key Web Lock `ortoolbox:tool-state:<tool>:<key>`. After a data reset a page's store refuses (`StateResetError`) to store a value from before it: a key the page read or wrote before the reset and has not read since, or an object it read or stored before (identity, so a merge-read before writing a pre-reset thread does not get it through). Deletes, new keys and values built after a fresh read go through. The guard is in storage, not on the bus: Reset bumps `kv` `meta:reset-generation` in the transaction that clears `kv` (`wipeKv`), reads note the generation they read in, and every `set` compares inside its own readwrite transaction, so IndexedDB orders it before the wipe (wiped) or after it (refused), in any tab, whenever `data-reset` arrives (an in-memory check before the `put` let one through). Reset (after its `data-reset`), "Delete all prompts and history", a per-tool delete and a backup import emit `tool-state-changed` for every key they remove or write, so open tools re-read and show it.
  - **Settings** `update()` re-reads storage before applying the mutator (no lost cross-tab updates); `pageshow` (bfcache) and becoming visible re-sync, except while storage is unavailable (what is shown stays). Numbers are clamped to sane ranges and `__proto__`/`constructor`/`prototype` keys are never copied. `reset()` keeps `defaultKeyId` (keys are not affected). An older tab drops fields of a newer schema version on its next write.
  - **Storage errors:** `writeJson` never pretends: blocked storage throws `StorageUnavailableError` (`storage-unavailable`), a full one `StorageFullError`. Every IndexedDB promise (requests, `tx.done`, the `db.put` shortcuts) comes from `getDb()`'s `guard` proxy, which turns quota errors into `StorageFullError` for every store.
